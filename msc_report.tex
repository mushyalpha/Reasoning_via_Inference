\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

This thesis develops and audits a pre-registered mechanistic Structural Causal Model (SCM) for diagnosing robotic grasp failure. Given a failed grasp attempt, we ask whether Pearl's three-step counterfactual procedure---abduction, action, and prediction---applied to an SCM derived from the known dataflow of the perception-action pipeline, can correctly attribute the failure to its environmental root cause when a single cause exists, and correctly recognise the failure as irreducibly multi-causal when it does not. Because the perturbations are experimenter-controlled, the true cause of each failure is always available for scoring against simulated ground truth, making this a falsifiable methodological audit rather than an unfalsifiable post-hoc narrative. As a secondary comparison, we contrast this structured diagnosis against a zero-shot vision-language model~(LLM) given identical observational data, to quantify what the SCM's explicit structural knowledge of the pipeline contributes relative to associative natural-language reasoning.

The SCM links four independently controllable perceptual variables---depth noise~($\sigma_d$), point cloud sparsity~($\rho$), viewpoint elevation~($\phi$), and viewpoint azimuth~($\theta$)---through measurable intermediate variables (point cloud completeness, grasp confidence, and pose error) to binary grasp success. The approach is implemented in MuJoCo with Contact-GraspNet as the grasp synthesis model, injecting synthetic Gaussian depth noise directly onto the simulated depth buffer to obtain perturbations that are causally clean and independently controlled, a level of experimental precision that is difficult to achieve on physical hardware. Across 432 trials spanning a full factorial grid over the four variables, depth noise emerges as the dominant cause of failure---grasp success falls monotonically from 70.4\% under a noise-free sensor to 0.0\% under the most severe noise condition, with viewpoint elevation and point cloud sparsity producing smaller effects that interact with depth noise rather than acting independently---and this descriptive finding establishes the failure regime against which the counterfactual audit, and the secondary SCM-vs-LLM comparison, are evaluated. The two diagnosticians are compared on attribution accuracy, consistency across repeated queries, and explanation quality.

\textbf{Keywords:} Causal Inference, Counterfactual Reasoning, Grasp Failure Diagnosis, Structural Causal Model, Point Cloud, MuJoCo, Contact-GraspNet, Large Language Models, Perceptual Degradation.

\chapter{Introduction}
\label{ch:intro}

\section{Motivation and Context}
\label{sec:motivation}

Data-driven grasp synthesis algorithms achieve high success rates under laboratory conditions. For example, Contact-GraspNet (CGN)~\cite{sundermeyer2021contact} achieves over 90\% grasp success on unseen objects in structured clutter, generating diverse grasps that cover the graspable surface of a scene. However, headline numbers like this are achieved under controlled conditions, including with a collision-aware selection stage that filters candidate grasps before execution, a well-calibrated environment, a favourable camera viewpoint, and a specified gripper. Achieving such high grasp success rates takes great engineering effort, as the MuJoCo experiments we carried out illustrate.

When deployed in the real world, these reported accuracies frequently fail to transfer. The constraints are combined effects of perception (depth sensor noise), geometry (unfavourable viewpoints causing partial observability), and physics (pre-grasp collisions, friction, and mass effects). Determining which layer is responsible for a given failure is hard. As a result, success or failure of a grasp cannot be decomposed back into its contributing causes. For example, is a failed grasp caused by a noisy depth image, an impossible overhead viewpoint, or a collision? Contact-GraspNet's opacity as a deep-learning model compounds this problem. Even a fully transparent version of the same algorithm would still not tell us, from outcome data alone, which layer was at fault in a given trial. When a grasp fails, the system knows only that it failed.

Because we cannot separate these layers observationally, diagnosing failure in autonomous robotics requires a structural model. Trustworthy autonomy demands that we know \emph{why} a trusted algorithm fails. This thesis argues that rather than treating benchmark shortfall as a reproduction failure, we must make the preconditions of success explicit and measure how much each one contributes to failure. Doing so requires a mechanistic causal audit of the perception-action pipeline.

\section{The Diagnostic Gap}
\label{sec:diagnostic_gap}

Existing approaches to handling grasp failure include retry policies, anomaly detection, reinforcement learning, statistical causal discovery, learned causal explanation, and vision-language models, which can detect failure and recover from it. However, they do not provide the kind of auditable structural diagnosis that attributes a specific failure to a specific cause. Chapter~\ref{ch:background} reviews these approaches in detail. What remains absent is an audit method that (a)~leverages the known computational architecture of the robot to build a structural model of failure and (b)~validates that model using a principled counterfactual test: \emph{if this particular structural precondition had been met, would the grasp have succeeded?}

\section{Thesis Approach: The Mechanistic Causal Audit}
\label{sec:approach}

This thesis addresses the diagnostic gap by formulating grasp failure diagnosis as a mechanistic causal audit. Rather than attempting to statistically learn a causal graph from noisy observational data, we use the known dataflow of the robot's perception-action pipeline to pre-register a Structural Causal Model (SCM)~\cite{pearl2009causality}.

To conduct this audit, we construct a fully controlled factorial experiment in MuJoCo that directly implements Pearl's do-operator. This environment allows us to isolate and manipulate four exogenous environmental variables: depth noise standard deviation~$\sigma_d$, point cloud retention fraction~$\rho$, camera elevation~$\phi$, and camera azimuth~$\theta$. The SCM links these controlled interventions to the binary grasp outcome~$Y$ through intermediate mechanistic variables: point cloud completeness~$C_{pc}$, grasp confidence~$q_{\text{grasp}}$, grasp pose error~$e_{\text{pose}}$, and the number of valid grasp candidates~$n_{\text{grasps}}$.

The audit is conducted entirely in simulation. The counterfactual test at the centre of this thesis requires rewinding a trial and re-executing it under an altered condition to obtain ground truth. No physical robot allows this, but simulation makes this possible. Therefore our conclusions describe failure mechanisms within a physically grounded simulation pipeline, but their transfer to physical hardware is not evaluated here.

To separate the layers of failure, the experimental pipeline adopts a two-arm design. The unfiltered arm measures how much the physical geometry of the scene accounts for failure; the filtered arm is the testbed on which we perform perceptual interventions. We isolate pose quality from full arm kinematics through a floating-gripper physics-based test, ensuring that the outcome variable strictly measures the validity of the perception-driven pose. Without filtering, geometry-driven invalid poses dominate and success rates remain low across the pre-registered viewpoint grid. Once the collision-filtering precondition that CGN's own pipeline implicitly assumes is replicated, and a favourable viewpoint is selected after inspecting the main grid, success reaches 89\%. This figure is a post-hoc scoping check of ideal-condition performance---a validity check that the testbed does not artificially suppress performance---rather than a claim of parity with any external benchmark.

Given an observed grasp failure, we apply Pearl's three-step counterfactual procedure~\cite{pearl2018book}---\emph{abduction}, \emph{action}, and \emph{prediction}---to identify which modelled environmental factor most likely caused the failure. Under full experimental control the exogenous settings ($\sigma_d$, $\rho$, $\phi$, $\theta$) are logged rather than inferred, so abduction is degenerate; the diagnostic work lies in the action and prediction steps, which ask whether intervening on a candidate cause would have saved the grasp. Because the testbed directly implements the do-operator, we are able to rewind the simulation and verify each such counterfactual against ground truth within the modelled environment. This establishes whether fixing the identified perceptual variable would have saved the grasp, or whether the failure was irreducibly constrained by physical geometry.

As a secondary comparison, we contrast this structured causal diagnosis against a zero-shot large language model (LLM) baseline, to illustrate what associative natural-language reasoning misses relative to a diagnosis grounded in the pipeline's known structure. The underlying model (Gemini~2.5~Flash) is VLM-capable; in this comparison, however, it receives only structured textual descriptions of each trial rather than images. The comparison is deliberately asymmetric, and that asymmetry is the point: the SCM's advantage is precisely that it encodes the pipeline's architecture; the comparison measures the value of that encoding, not the relative intelligence of either system. On identical failure cases, we test whether SCM-based counterfactual reasoning identifies the root cause of a grasp failure---or correctly recognises that no single cause suffices---more reliably than a zero-shot LLM. The counterfactual machinery further shows that a majority of failures (57.2\%, within the intervention magnitudes tested) resist single-cause attribution even after formal diagnosis, reflecting the complexity of failure modes in physical execution.

\section{Aim and Objectives}
\label{sec:aims}

\paragraph{Aim.} To determine whether a pre-registered mechanistic Structural Causal Model, audited through Pearl's counterfactual procedure, enables auditable diagnosis of robotic grasp failure---including recognition of irreducibly multi-causal failures---checked against simulated ground truth. A diagnosis is correct if it attributes the failure to the right single structural variable when one exists, or recognises the failure as irreducibly multi-causal when it does not. As a secondary aim, we compare this structured diagnosis against a zero-shot large language model given the same observational data, to quantify what explicit structural knowledge of the pipeline contributes relative to associative natural-language reasoning.

\paragraph{Objectives.} To achieve this aim, the thesis pursues five objectives:

\begin{enumerate}
    \item \textbf{Build a Fully Controlled Testbed:} Construct a physics-grounded simulation pipeline capable of executing automated grasping trials under precisely controlled perceptual degradations. Establish a baseline ceiling using a favourable viewpoint identified after inspecting the main grid, as a post-hoc scoping check of ideal-condition performance rather than a pre-registered claim.
    \item \textbf{Characterise Pose Validity under Clean Conditions:} Quantify pre-grasp collision as a baseline failure mode, measuring how much of the accuracy gap is accounted for by geometry alone versus perceptual degradation.
    \item \textbf{Model the Causal Structure:} Pre-register and validate a nonparametric Structural Causal Model based on the known computational dataflow of the perception-action pipeline, and state in advance the conditions under which that model could be falsified.
    \item \textbf{Perform Counterfactual Diagnosis:} Apply Pearl's abduction-action-prediction procedure to observed failures to identify root causes. This includes recognising when a failure is irreducibly multi-causal, and validating these diagnoses against simulated ground-truth counterfactuals.
    \item \textbf{Evaluate against a Secondary Baseline:} As a supporting comparison, contrast the SCM's diagnostic accuracy, consistency, and interpretability against a zero-shot LLM given identical observational data, to quantify the value added by explicit structural knowledge relative to associative reasoning.
\end{enumerate}

\section{Contributions}
\label{sec:contributions}

The core contributions of this thesis are:

\begin{enumerate}
    \item \textbf{A Mechanistic Structural Causal Model:} An SCM for grasp failure that is derived directly from system architecture, featuring four independently intervenable scene variables and four measurable intermediate variables.
    \item \textbf{A Fully Controlled Factorial Testbed:} A complete simulation environment in MuJoCo~\cite{todorov2012mujoco} that directly implements Pearl's do-operator.     \item \textbf{Baseline Separation of Geometry from Perception:} Geometry-driven invalid poses are shown to dominate failure without collision filtering.     \item \textbf{Counterfactual Evaluation Pipeline:} An end-to-end pipeline executes Pearl's counterfactual procedure to diagnose failures against simulated ground truth and, as a secondary contribution, compares this structured causal diagnosis against LLM-based attribution on identical cases.

\section{Structural Causal Models and Counterfactuals}
\label{sec:bg_scm}

The framework of Structural Causal Models, developed by Pearl~\cite{pearl2009causality}, provides a rigorous mathematical foundation for reasoning about cause and effect. The causal structure is represented as a \emph{directed acyclic graph} (DAG), where each node corresponds to a variable and each directed edge $V_i \to V_j$ indicates that $V_i$ is a direct cause of $V_j$ in the model. An SCM assigns a structural equation to each node, formalising the mechanism by which a variable is produced from its graph-theoretic parents.

\begin{definition}[Structural Causal Model]
A Structural Causal Model is a triple $\SCM = (\mathbf{U}, \mathbf{V}, \mathbf{F})$ where:
\begin{itemize}
  \item $\mathbf{U}$ is a set of \emph{exogenous} (background) variables whose values are determined by factors outside the model.
  \item $\mathbf{V} = \{V_1, V_2, \ldots, V_n\}$ is a set of \emph{endogenous} variables whose values are determined by the structural equations.
  \item $\mathbf{F} = \{f_1, f_2, \ldots, f_n\}$ is a set of \emph{structural equations}, where each $f_i$ expresses $V_i$ as a function of its parent variables (a subset of $\mathbf{V} \cup \mathbf{U}$): $V_i = f_i(\text{pa}(V_i), U_i)$.
\end{itemize}
\end{definition}

\paragraph{The do-operator and interventional reasoning.}
Causal effects are formalised via the \emph{do-operator}: the expression $\doop(X = x)$ denotes an intervention that sets variable $X$ to value $x$ by removing all incoming edges to $X$ in the causal graph and fixing its value, regardless of what its structural equation would normally produce~\cite{pearl2009causality}. The distinction between the do-operator and ordinary conditioning is fundamental. The conditional probability $P(Y \mid X = x)$ reflects both causal and non-causal (e.g., confounded) associations between $X$ and $Y$. The interventional distribution $P(Y \mid \doop(X = x))$ reflects only the causal effect of $X$ on $Y$, because the intervention removes the influence of confounders that act through $X$'s parents.

\paragraph{The Pearl Causal Hierarchy.}
These three modes of reasoning---observational, interventional, and counterfactual---correspond to the three layers of the \emph{Pearl Causal Hierarchy} (PCH)~\cite{pearl2009causality}: $\mathcal{L}_1$ (seeing: $P(Y \mid X)$), $\mathcal{L}_2$ (doing: $P(Y \mid \doop(X))$), and $\mathcal{L}_3$ (imagining: $P(Y_x \mid x')$). Yang and Bareinboim~\cite{yang2025hierarchy} formalise this hierarchy through a corresponding sequence of graphical model classes---Bayesian Networks, Causal Bayesian Networks, and Counterfactual Bayesian Networks---and prove that each level encodes strictly stronger constraints than those below, with a commensurate reduction in empirical falsifiability. This thesis operates at $\mathcal{L}_3$: the counterfactual queries in Chapter~\ref{ch:formulation} ask what \emph{would} have happened to a specific observed trial under a hypothetical change to conditions, which requires the full expressive power of the SCM.

\paragraph{Parametric versus non-parametric SCMs.} Vonk et al.~\cite{vonk2023disentangling} note that structural causal models can be specified either \emph{non-parametrically}, where each $f_i$ is left as an arbitrary function and only qualitative properties (e.g.\ monotonicity) are assumed, or \emph{parametrically}, where a specific functional form is fixed in advance. Non-parametric specification is preferred when possible because it avoids the risk of functional-form misspecification, but it is frequently infeasible with a limited number of observations, since arbitrary functions cannot be estimated from finitely many trials without additional structure. This thesis adopts a parametric SCM: the structural equations in Section~\ref{sec:structural_equations} are linear-in-parameters (with a logistic link for the binary outcome). This choice is deliberate and its cost is discussed explicitly in Section~\ref{sec:structural_equations} and revisited in Section~\ref{sec:limitations}.

\subsection{Pearl's Three-Step Counterfactual Procedure}

Counterfactual reasoning extends interventional reasoning by asking questions about specific individuals or events: \emph{given what actually happened, what would have happened if conditions had been different?} Pearl's three-step procedure~\cite{pearl2018book} formalises this:

\begin{enumerate}
  \item \textbf{Abduction.} Given the observed evidence $\mathbf{e}$ (the values of all measured variables in the actual world), infer the values of the exogenous noise terms $\mathbf{U}$ that are consistent with $\mathbf{e}$. In a deterministic SCM, this amounts to solving the structural equations for the noise terms:
  \begin{equation}
    U_i = V_i^{\text{obs}} - f_i(\text{pa}(V_i)^{\text{obs}}).
    \label{eq:abduction}
  \end{equation}
  This step ``personalises'' the model to the specific observed instance.

  \item \textbf{Action.} Apply the hypothetical intervention $\doop(X = x')$ to the model by replacing the structural equation for $X$ with the constant assignment $X = x'$.

  \item \textbf{Prediction.} Propagate the modified structural equations forward, using the abducted noise terms from Step~1, to compute the counterfactual outcome $Y_{X=x'}$.
\end{enumerate}

The counterfactual outcome $Y_{X=x'}$ is the value that $Y$ \emph{would have taken} in the specific observed instance if $X$ had been set to $x'$ instead of its actual value, with all other exogenous factors held at their abducted values. This is a statement about a specific individual event, not a population-level statistic.

\section{Robotic Grasp Failure and Recovery}
\label{sec:bg_grasp}

Grasp failure has been approached through model-based, data-driven, and tactile feedback methods. The landscape of grasp synthesis has evolved significantly over the past decade, moving from analytical methods based on force closure and form closure to data-driven approaches that learn grasp proposals directly from sensor observations.

Learned grasp planners such as GraspNet-1Billion~\cite{fang2020graspnet} and Contact-GraspNet~\cite{sundermeyer2021contact} represent the current state of the art. These models achieve strong performance under clean sensing conditions but are sensitive to the quality of the input data. When the point cloud is sparse, noisy, or incomplete due to viewpoint limitations, these models produce grasp proposals that may be geometrically infeasible.

Tactile feedback systems offer an alternative pathway for detecting grasp failure. Systems based on GelSight sensors and similar tactile technologies can detect slippage after contact has been established~\cite{calandra2018more}. However, tactile feedback operates at a different stage of the grasping pipeline: it can detect that a grasp is failing \emph{during execution} but cannot diagnose why a vision-based grasp \emph{proposal} was incorrect \emph{before} contact is made. The failure modes addressed in this thesis occur upstream of contact, in the perception-to-planning pathway.

The most common recovery strategy in deployed robotic systems remains a fixed retry policy: if a grasp fails, the system attempts the same or a slightly perturbed grasp. This approach implicitly assumes that failures are stochastic and that the underlying conditions are unchanged. When failures are caused by systematic perceptual problems---such as a viewpoint that consistently fails to observe a critical surface---retry policies are ineffective.

\section{Approaches to Grasp Failure Diagnosis}
\label{sec:bg_diagnosis}

Section~\ref{sec:diagnostic_gap} identified the absence of an auditable structural diagnosis for grasp failure. This section reviews the main existing responses and situates the closest causal prior work relative to the present thesis.

\textbf{Retry strategies.} The most common response is to retry the grasp with a slightly perturbed pose~\cite{hsiao2010contact}. If the failure was caused by a systematic geometric problem---such as a viewpoint that consistently obscures a critical surface---retrying will produce the same failure repeatedly. Retry policies therefore address recovery, not diagnosis.

\textbf{Anomaly detection.} Methods based on force/torque or tactile sensors can identify \emph{when} something has gone wrong during a grasp attempt~\cite{park2018multimodal}. However, detecting that a failure occurred is fundamentally different from isolating its structural root cause.

\textbf{Reinforcement learning.} Learning-based approaches improve future performance by training on past failures~\cite{levine2018learning, kalashnikov2018scalable}. While they implicitly encode information about failure modes, their learned representations are mathematically opaque, making it impossible to extract a human-understandable diagnosis.

\textbf{Causal discovery.} Traditional causal inference often relies on causal discovery---attempting to statistically learn a causal graph from observational data. In robotics, observational data is heavily confounded by physical dynamics. However, for a deployed robotic pipeline, the system's computational architecture (from camera, to point cloud, to neural network, to kinematics) is already known, making statistical graph discovery an unnecessary compromise.

\textbf{Causal robot-failure explanation.} The closest prior work targets causal explanation of robot failures directly. Diehl and Ramirez-Amaro~\cite{diehl2022whydidifail} learn a causal Bayesian network from simulation data and generate contrastive explanations by searching for the nearest counterfactual state that would have succeeded. This shares our goal of structural, causal explanation. However, the causal graph is \emph{learned} rather than pre-registered from known system architecture, and the method targets manipulation tasks such as block-stacking rather than a perception-driven grasp-synthesis pipeline with controlled degradation of a sensing stage. Causal robotics benchmarks such as CausalWorld~\cite{ahmed2021causalworld} similarly expose intervenable causal variables in a manipulation simulator. However, they target transfer learning and policy generalisation rather than post-hoc diagnosis of a fixed, pre-trained perception model.

\textbf{Vision-language models.} Large vision-language models can provide natural-language explanations of observed phenomena~\cite{ahn2022saycan, driess2023palm}. However, their diagnoses are highly sensitive to prompt phrasing, often rely on surface-level correlations rather than structural physics, and lack a built-in mechanism for validation against ground truth. Section~\ref{sec:bg_llm} reviews their broader use in robotics and motivates their role as a zero-shot baseline in this thesis.

What remains absent, and what this thesis supplies, is an audit method that (a)~pre-registers a structural model of failure from the known computational architecture of the robot, and (b)~validates that model with a principled counterfactual test against simulated ground truth.

\section{Depth Sensor Noise Characterisation}
\label{sec:bg_depth}

Real depth sensors such as the Intel RealSense D400 series and the Microsoft Kinect exhibit characteristic noise patterns that depend on the sensing technology. Structured-light sensors (e.g., the original Kinect) project an infrared pattern onto the scene and infer depth from the deformation of that pattern. Time-of-flight sensors (e.g., the Kinect v2 and Azure Kinect) measure the round-trip time of modulated infrared light.

Khoshelham and Elberink~\cite{khoshelham2011accuracy} conducted a detailed analysis of Kinect depth noise and found that the axial noise (error in the measured depth) grows approximately proportionally with the square of the distance from the sensor. The standard deviation of depth noise at 1~m was approximately 1--2~mm, increasing to approximately 40~mm at 5~m. The noise also increases with the angle of incidence: surfaces viewed at steep angles produce noisier measurements because fewer infrared photons are reflected back to the sensor.

Nguyen et al.~\cite{nguyen2012modeling} proposed a more detailed noise model that includes both axial and lateral components, showing that the lateral noise (error perpendicular to the line of sight) is typically larger than the axial noise at the same distance. However, for the purposes of point cloud generation---where the dominant effect is the distortion of the three-dimensional geometry---the axial noise captured by the Gaussian model is the primary concern.

The additive Gaussian noise model $d_{\text{noisy}} = d_{\text{true}} + \mathcal{N}(0, \sigma_d^2)$ is the standard first-order approximation used in depth simulation pipelines. While this model does not capture structured noise patterns (such as the failure of IR depth measurement near specular surfaces or the systematic bias at depth discontinuities), it provides a parametrically controllable surrogate that captures the essential characteristic: depth measurements are corrupted by stochastic errors whose magnitude is controlled by a single parameter $\sigma_d$.

\section{Contact-GraspNet}
\label{sec:bg_cgn}

Contact-GraspNet~(CGN)~\cite{sundermeyer2021contact} is a neural network model for 6-DoF grasp generation from point cloud observations. The model takes as input a partial point cloud of a scene and outputs a set of grasp proposals, each consisting of a 4$\times$4 homogeneous transformation matrix (representing the 6-DoF pose of the gripper) and a scalar confidence score.

The key architectural innovation of CGN is its use of \emph{contact points}: rather than regressing grasp poses directly from global point cloud features, CGN predicts, for each point in the cloud, the probability that it is a valid contact point for a parallel-jaw gripper, along with the associated grasp pose parameters. This contact-centric representation allows CGN to generate grasps that are geometrically grounded in the observed surface, which contributes to its strong performance under clean conditions.

CGN was trained on a large-scale synthetic dataset generated from ShapeNet object meshes. The training data includes a diverse set of object geometries, which gives CGN reasonable generalisation to novel objects. However, the training data was generated under clean sensing conditions (no depth noise, no extreme viewpoints), which means that CGN's performance under degraded inputs may differ from its training distribution.

For this thesis, CGN serves as the ``black box'' grasp synthesis component: we do not modify CGN's architecture or retrain it, but instead study how its outputs (grasp proposals and confidence scores) are affected by controlled perturbations to its inputs (depth noise and point cloud sparsity). This is precisely the relationship that the Structural Causal Model is designed to capture.

\section{Large Language Models in Robotics}
\label{sec:bg_llm}

Recent work has explored the integration of large language models into robotic decision-making systems. SayCan~\cite{ahn2022saycan} demonstrated that LLMs can provide high-level task planning by grounding language instructions in the robot's physical affordances. Code as Policies~\cite{liang2023code} showed that LLMs can generate executable robot control code from natural-language task descriptions. VoxPoser~\cite{huang2023voxposer} used LLMs to compose 3D value maps for robotic manipulation.

These systems demonstrate the impressive generalisation capabilities of LLMs across robotic tasks. However, they operate primarily at the task-planning level and assume that the underlying perception is correct. When perception fails---when the depth sensor produces noisy measurements, or the viewpoint provides insufficient coverage---these systems have no mechanism to diagnose the failure or identify its cause.

PaLM-E~\cite{driess2023palm} represents a step toward multimodal robotic reasoning by combining vision and language in a single model. While such models can reason about visual scenes, their reasoning process is opaque and their outputs are not guaranteed to be consistent across repeated queries.

Evaluating an LLM as a zero-shot failure attribution baseline provides a natural comparison point for this thesis: the LLM requires no task-specific training, can be applied to any failure case with appropriate prompting, and represents the current state of practice for unstructured failure reasoning. The comparison tests whether the structured causal reasoning provided by the SCM offers diagnostic value beyond what zero-shot vision-language reasoning can achieve.

\chapter{Problem Formulation}
\label{ch:formulation}

This chapter formalises the problem of grasp failure diagnosis as a causal inference problem. We define the variables of interest, specify the causal graph that encodes their relationships, derive the structural equations, and state the research hypotheses.

\section{Variables}
\label{sec:variables}

\subsection{Exogenous Variables (Controlled by Experimenter)}

The exogenous variables are the factors that the experimenter directly controls in each trial. They represent the environmental conditions under which the grasp is attempted. A terminological clarification is necessary here: this thesis uses ``exogenous'' in two related but distinct senses. First, $\sigma_d, \rho, \phi, \theta$ are exogenous in the graphical sense---they have no parents in the causal DAG of Figure~\ref{fig:causal_dag}---and their mutual independence is guaranteed by the full factorial design (every combination of values is assigned by the experimenter, not sampled from an uncontrolled process). Second, each structural equation in Section~\ref{sec:structural_equations} contains a distinct exogenous \emph{noise term} $U_i$ (e.g.\ $U_C, U_q, U_n, U_e$), representing unmodelled factors internal to the mechanism itself (segmentation noise, CGN's internal stochasticity, pose-regression error). It is the independence properties of these noise terms, not of $\sigma_d, \rho, \phi, \theta$, that determine whether the model is Markovian in the sense required for the counterfactual identification argument of Section~\ref{sec:counterfactual_diagnosis}.

\begin{itemize}
  \item $\sigma_d \in \{0,\, 0.005,\, 0.02,\, 0.04\}$\,m: the standard deviation of Gaussian depth noise injected per pixel onto the MuJoCo depth buffer. The value $\sigma_d = 0$ represents a perfect sensor with no noise. The value $\sigma_d = 0.005$\,m (5\,mm) approximates the noise level of a high-quality commercial depth sensor at typical operating distances~\cite{khoshelham2011accuracy}. The values $\sigma_d = 0.02$\,m and $\sigma_d = 0.04$\,m represent progressively more severe degradation, corresponding to sensors operating at the limits of their range or in adverse conditions.

  \item $\rho \in \{1.0,\, 0.75,\, 0.50,\, 0.25\}$: the fraction of points retained after random downsampling of the full point cloud. This variable operationalises point cloud sparsity. The value $\rho = 1.0$ means the full point cloud is used; $\rho = 0.25$ means that 75\% of the points are randomly removed before the point cloud is passed to Contact-GraspNet. This models scenarios where limited sensor resolution, bandwidth constraints, or computational budgets necessitate working with sparse point clouds.

  \item $\phi \in \{30°,\, 45°,\, 60°\}$: the elevation angle of the camera, measured from the horizontal plane, on a fixed-radius sphere (0.8\,m) centred on the target object. Lower elevations provide more of a ``side view'' of the object, while higher elevations look down more steeply. Elevation affects which surfaces of the object are visible and the effective spatial resolution of the depth measurement on horizontal surfaces.

  \item $\theta \in \{0°,\, 45°,\, 90°\}$: the azimuth angle of the camera on the same sphere. Azimuth determines the horizontal viewing direction and affects which side of the object is observed. Combined with elevation, it fully specifies the camera's position on the viewing sphere.
\end{itemize}

\subsection{Endogenous Variables (Measured per Trial)}

The endogenous variables are quantities that are measured or computed during each trial. They are not directly controlled by the experimenter but are influenced by the exogenous variables through the causal mechanisms encoded in the structural equations:

\begin{itemize}
  \item $C_{pc}$: the fraction of image pixels belonging to the target object, measuring geometric visibility from the current viewpoint. This is computed from the MuJoCo segmentation buffer. A higher $C_{pc}$ indicates that the object occupies a larger fraction of the image and is therefore better resolved by the depth sensor.

  \item $q_{\text{grasp}}$: the Contact-GraspNet top-1 confidence score for the selected grasp pose. This is a scalar value in $[0, 1]$ (though in practice CGN scores are typically in the range $[0.1, 0.3]$) that reflects CGN's estimate of the likelihood that the proposed grasp will succeed. Higher scores indicate greater confidence.

  \item $e_{\text{pose}}$: the Euclidean distance (in metres) between the CGN-proposed gripper position in world coordinates and the true object centroid. This is the primary measure of perception-induced grasp error. Under clean conditions, $e_{\text{pose}}$ is typically small (1--3\,cm); under severe degradation, it can exceed 15\,cm.

  \item $n_{\text{grasps}}$: the total number of valid grasp candidates generated by CGN on this trial's point cloud. Under clean conditions ($\sigma_d = 0$, $\rho = 1.0$), CGN generates between 4 and 152 candidates (mean $\approx 47$), with wide variation depending on viewpoint; at $\phi = 45°$, $\theta = 0°$ the count reaches 120--150, while at $\phi = 30°$, $\theta = 90°$ it drops to single digits. Under severe noise ($\sigma_d = 0.04$), the mean falls to $\approx 1.2$, and 141 of the 432 trials (32.6\%) produced zero grasps (the ``no grasps'' condition).

  \item $Y \in \{0, 1\}$: binary grasp success. The operationalisation of this variable is described in detail in Section~\ref{sec:success_criterion_detail}.
\end{itemize}

\section{Causal Graph}
\label{sec:causal_graph}

The causal relationships between the variables are encoded in the directed acyclic graph shown in Figure~\ref{fig:causal_dag}. The graph reflects the following causal assumptions:

\begin{enumerate}
  \item Point cloud completeness $C_{pc}$ is causally affected by camera viewpoint ($\phi$, $\theta$) only. Depth noise $\sigma_d$ and point cloud sparsity $\rho$ are \emph{not} parents of $C_{pc}$: $C_{pc}$ is computed from the MuJoCo segmentation buffer, which is rendered before noise is injected and before the point cloud is downsampled, so neither variable can affect it by construction. An earlier version of this graph hypothesized direct edges from all four exogenous variables to $C_{pc}$; Section~\ref{sec:falsification} reports the pre-specified test that falsified the $\sigma_d \to C_{pc}$ and $\rho \to C_{pc}$ edges, and this is the version of the graph after that revision.

  \item Depth noise $\sigma_d$ has direct causal effects on both $q_{\text{grasp}}$ and $e_{\text{pose}}$, beyond its indirect effect through $C_{pc}$. This reflects the fact that noise corrupts the point cloud geometry in ways that affect grasp quality even when the overall coverage is unchanged.

  \item Viewpoint parameters ($\phi$, $\theta$) have direct effects on $e_{\text{pose}}$ because the viewing angle determines which surfaces are observed, which in turn affects the accuracy of CGN's pose estimation independently of overall coverage.

  \item The intermediate variables ($C_{pc}$, $q_{\text{grasp}}$, $n_{\text{grasps}}$, $e_{\text{pose}}$) jointly determine the binary outcome $Y$.
\end{enumerate}

\section{Structural Equations}
\label{sec:structural_equations}

The SCM is parameterised as a set of regression models. The choice of linear models for the continuous intermediate variables is motivated by interpretability and by the expectation that, within the range of the experimental grid, the relationships are approximately monotone. The outcome model uses logistic regression because $Y$ is binary.

This is a deliberate parametric commitment, and it is not without cost. As noted in Section~\ref{sec:bg_scm}, fixing a functional form in advance means that any systematic non-linearity in the true mechanism that is not captured by the chosen basis functions (here, low-order polynomials and the trigonometric terms $\sin\phi$, $\cos\theta$) will appear as model misspecification rather than as noise. A concrete instance of this cost is visible in the data: Contact-GraspNet exhibits a systematic, viewpoint-specific lateral bias of approximately 6\,cm at $\phi = 30°$ (see the discussion following Equation~\eqref{eq:ep} below) that is a genuine non-linear, threshold-like effect of viewpoint on pose error. The linear term $\delta_3 \phi$ in Equation~\eqref{eq:ep} can only approximate this as a global slope; it cannot represent a bias that is large at one specific elevation and small elsewhere. We accept this cost for three reasons. First, non-parametric estimation of four structural equations from 432 (426 usable) trials is not well supported: with four exogenous variables and up to three intermediate parents per equation, a fully non-parametric model would require substantially more data than is available to avoid overfitting. Second, the linear-logistic form keeps every coefficient directly interpretable as a signed effect size, which is essential for the counterfactual attribution procedure in Section~\ref{sec:counterfactual_diagnosis} and for the mediation analysis in Section~\ref{sec:scm_fit}. Third, the parametric choice is falsifiable and its fit quality is reported directly (Section~\ref{sec:scm_fit}), rather than assumed; where the linear fit is poor (as for the $\phi = 30°$ bias), this is flagged explicitly rather than absorbed silently into the residual. Investigating non-linear (e.g.\ neural) parameterisations of these equations, which would relax this assumption at the cost of interpretability and data efficiency, is identified as future work in Chapter~\ref{ch:discussion}.

\subsection{Point Cloud Completeness}

The structural equation for $C_{pc}$ models how the viewpoint variables determine the fraction of pixels occupied by the target object:
\begin{equation}
  C_{pc} = \beta_0 + \beta_1 \sin\phi + \beta_2 \cos\theta + U_C,
  \label{eq:cpc}
\end{equation}
where $U_C$ is the exogenous noise term representing all other factors that affect point cloud completeness but are not modelled. Depth noise $\sigma_d$ and sparsity $\rho$ do not appear in this equation: an earlier specification included both as predictors, but the pre-specified falsification test in Section~\ref{sec:falsification} found no measurable partial effect of either variable on $C_{pc}$, consistent with $C_{pc}$ being computed from the segmentation buffer before noise injection and downsampling occur in the pipeline. The equation was revised accordingly rather than retaining the terms and absorbing the null effect into $U_C$. The trigonometric transformations $\sin\phi$ and $\cos\theta$ are used because the relationship between viewing angle and visible area is inherently non-linear. At low elevations ($\phi \approx 30°$), small changes in elevation produce large changes in the fraction of the top surface visible, while at higher elevations the relationship saturates. The sine function captures this approximately.

\subsection{Grasp Confidence}

The structural equation for $q_{\text{grasp}}$ models how the CGN confidence score depends on point cloud quality:
\begin{equation}
  q_{\text{grasp}} = \gamma_0 + \gamma_1 C_{pc} + \gamma_2 \sigma_d + U_q.
  \label{eq:qg}
\end{equation}
The direct dependence on $\sigma_d$ (beyond the indirect path through $C_{pc}$) reflects the fact that noise corrupts the point cloud geometry in ways that reduce CGN's confidence even when overall coverage is unchanged. The noise term $U_q$ captures the stochasticity inherent in CGN's scoring across different random seeds and noise realisations.

\subsection{Number of Grasp Candidates}

The structural equation for $n_{\text{grasps}}$ models the total number of valid grasp proposals:
\begin{equation}
  n_{\text{grasps}} = \eta_0 + \eta_1 C_{pc} + \eta_2 \sigma_d + \eta_3 \rho + U_n.
  \label{eq:ng}
\end{equation}
This variable is particularly sensitive to the point cloud quality: under severe noise ($\sigma_d = 0.04$), CGN frequently produces zero grasps because the corrupted point cloud does not contain any regions that the network identifies as graspable.

\subsection{Grasp Pose Error}

The structural equation for $e_{\text{pose}}$ models the Euclidean distance between the proposed and true grasp positions:
\begin{equation}
  e_{\text{pose}} = \delta_0 + \delta_1 C_{pc} + \delta_2 \sigma_d
                    + \delta_3 \phi + \delta_4 \theta + U_e.
  \label{eq:ep}
\end{equation}
The direct dependence on $\phi$ and $\theta$ reflects the observation that certain viewpoints produce systematic biases in CGN's pose estimation. For example, at $\phi = 30°$, CGN consistently proposes positions approximately 6\,cm from the true centroid, even with clean inputs. This is a property of CGN's training distribution rather than a perception error \emph{per se}, but it is modelled as a causal effect of viewpoint on pose error.

\subsection{Binary Outcome}

The outcome model is a logistic regression:
\begin{equation}
  P(Y = 1) = \sigma\!\left(\lambda_0 + \lambda_1 q_{\text{grasp}}
              + \lambda_2 n_{\text{grasps}} + \lambda_3 e_{\text{pose}}\right),
  \label{eq:Y}
\end{equation}
where $\sigma(\cdot)$ is the logistic sigmoid function $\sigma(z) = 1/(1 + e^{-z})$. The logistic model naturally maps the real-valued linear predictor to a probability in $[0, 1]$, which is then thresholded at 0.5 to produce the binary prediction.

\section{Falsification Conditions}
\label{sec:falsification}

A structural causal model that could not, even in principle, be contradicted by data is not a scientific model of the pipeline; it is a restatement of the researcher's assumptions dressed up as a diagnosis. Before presenting any results, we therefore state in advance what would count as evidence against the graph of Figure~\ref{fig:causal_dag} and against the fitted structural equations, and where in this thesis that evidence is reported. Two distinct objects are involved here, and it is important not to conflate them: the MuJoCo~+~Contact-GraspNet \emph{simulator} is treated as ground truth throughout this thesis (Section~\ref{sec:approach}); the SCM is a \emph{model of} that simulator, built from domain knowledge of its dataflow, and it is the SCM---not the simulator---that is on trial here.

\paragraph{(a) Conditional independencies implied by the graph.} The DAG of Figure~\ref{fig:causal_dag} asserts a specific set of edges and, by omission, a specific set of non-edges. Each non-edge is a testable conditional-independence claim: for instance, the absence of a direct edge $\sigma_d \to C_{pc}$ implies that $\sigma_d$ should carry no additional explanatory power for $C_{pc}$ once $\phi$ and $\theta$ are controlled for. Because $\sigma_d, \rho, \phi, \theta$ are assigned by a full factorial design rather than sampled from an uncontrolled process, every such conditional test is an interventional ($\mathcal{L}_2$) test of the graph, not merely an observational correlation. Table~\ref{tab:falsification} summarises the pre-specified tests and their outcomes, run against the 426-trial analysis sample (full detail in \texttt{results/dag\_edge\_falsification\_report.md}).

Two of the six pre-specified tests came back against the originally pre-registered graph, and both concern $C_{pc}$. The original specification asserted that all four exogenous variables affect point cloud completeness (a claim that is mechanistically plausible on its face, since all four describe some aspect of sensing quality); this is wrong for this particular pipeline, because $C_{pc}$ is computed from the segmentation buffer, which is rendered \emph{before} depth noise is injected and \emph{before} the point cloud is downsampled, so $\sigma_d$ and $\rho$ cannot affect it by construction. The data confirm this directly (Table~\ref{tab:falsification}), so the graph (Section~\ref{sec:causal_graph}, Assumption 1) and Equation~\eqref{eq:cpc} were revised to remove both edges rather than retaining them and letting the discrepancy disappear silently into the noise term $U_C$. We report this revision explicitly because it is the clearest available evidence that the graph is a falsifiable claim about this pipeline, not an unfalsifiable restatement of it: it was tested, part of it was wrong, and the model was changed as a result. The $\rho \to \text{has-grasps}$ edge is retained despite a non-significant coefficient at $n=426$, because it is implied directly by the pipeline's dataflow (fewer points can only reduce, never increase, the chance that CGN identifies a graspable region) and by the wider literature on point-cloud density and learned grasp detection; a null result at this sample size is flagged as a limitation on statistical power rather than treated as confirmation of no effect.

\paragraph{(b) Held-out interventional predictions.} Beyond conditional-independence tests on the graph's structure, the fitted structural equations make quantitative predictions about $P(Y \mid \doop(v))$ that can be checked against a statistic computed independently of the OLS/logistic fit itself: the stratified, model-free total-effect and path-decomposition estimates reported in \texttt{results/scm\_nonparametric\_report.md} (means and Wilson-score proportions computed directly from the factorial grid, with no line fitted to them). Where a structural equation's linear-in-parameters prediction diverges from this model-free estimate---as it does for the CGN pose bias at $\phi=30°$ discussed in Section~\ref{sec:structural_equations}---this divergence is reported as a specific, located failure of the parametric surrogate rather than smoothed over in the write-up. This is a genuine instance of the surrogate being shown, quantitatively, to be an imperfect model of the simulator it approximates.

Together, (a) and (b) fix in advance what evidence would count against the graph and against the fitted equations, and record that some of it did count against the original specification. This is offered as the basis on which the SCM's later agreement with simulated ground truth (Chapter~\ref{ch:results}) should not be read as circular: the graph was stated as a falsifiable claim, part of it was checked and revised in response to evidence, and the surrogate's known failure modes are disclosed rather than hidden.

\section{Defining Single-Cause, Multi-Cause, and Irreducible Failure}
\label{sec:single_cause_def}

Hypothesis~\ref{hyp:accuracy} below, the 57.2\% figure reported in Chapter~\ref{ch:results}, and Contribution 4 of this thesis (Section~\ref{sec:contributions}) all depend on a precise definition of what counts as a ``single cause,'' so we fix it here rather than leaving it implicit until the results are presented. For an observed failure with conditions $\mathbf{x}^* = (\sigma_d^*, \rho^*, \phi^*, \theta^*)$ and outcome $Y^*=0$, let $Y(v \!\to\! v_{\text{nom}})$ denote the outcome obtained by resetting exogenous variable $v$ alone to its nominal clean-baseline value ($\sigma_d = 0$, $\rho = 1.0$, $\phi = 45°$, $\theta = 0°$) while holding the remaining three variables at their observed values in $\mathbf{x}^*$. Then:

\begin{itemize}
  \item The failure is \textbf{single-cause} with respect to $v$ if $Y(v \!\to\! v_{\text{nom}}) = 1$ for exactly one $v \in \{\sigma_d, \rho, \phi, \theta\}$.
  \item The failure is \textbf{multi-cause} if $Y(v \!\to\! v_{\text{nom}}) = 1$ for more than one $v$ (fixing any one of several variables would have saved the trial).
  \item The failure is \textbf{irreducible} (reported as \texttt{none}) if $Y(v \!\to\! v_{\text{nom}}) = 0$ for every $v$: no single-variable reset to the clean baseline suffices.
\end{itemize}

Two aspects of this definition are worth making explicit rather than leaving implicit. First, it is anchored to a specific \emph{intervention magnitude}: a full reset of one variable to its nominal clean-baseline value, not a partial or graded correction. The reported irreducibility rate is therefore a statement about failures that resist this particular class of intervention, not about irreducibility in some magnitude-independent sense; Chapter~\ref{ch:discussion} returns to how sensitive the 57.2\% figure is to this choice. Second, the definition is evaluated against simulated ground truth (Section~\ref{sec:counterfactual_diagnosis} details how $Y(v \!\to\! v_{\text{nom}})$ is obtained, either by re-simulation or by a fitted surrogate), not against the SCM's own prediction of itself, which is what keeps the resulting classification from being tautological.

\section{Research Hypotheses}
\label{sec:hypotheses}

Based on the formulation above, we state three research hypotheses:

\begin{hypothesis}
  Counterfactual diagnosis over the fitted SCM will attribute single-cause grasp failures to the correct root variable in the majority of test cases.
  \label{hyp:accuracy}
\end{hypothesis}

\begin{hypothesis}
  Causal counterfactual diagnosis will achieve higher attribution accuracy than zero-shot vision-language model diagnosis on the same failure cases.
  \label{hyp:comparison}
\end{hypothesis}

\begin{hypothesis}
  LLM-based attribution will be less consistent across repeated queries than the deterministic SCM-based attribution.
  \label{hyp:consistency}
\end{hypothesis}

\chapter{Proposed Pipeline}
\label{ch:method}

This chapter describes the end-to-end pipeline for each experimental trial, from camera positioning to outcome evaluation. The pipeline is fully automated: no human operator intervenes at any stage. The physics simulation is stepped forward programmatically, with joint commands computed and applied at each timestep by the controller software.

\section{Pipeline Overview}
\label{sec:pipeline_overview}

Each of the 432 experimental trials proceeds through the following stages:

\begin{enumerate}
  \item \textbf{Scene initialisation.} Load the MuJoCo scene from \texttt{grasp\_scene\_v2.xml}, reset to the home keyframe, and run \texttt{mj\_forward} to initialise the physics state.

  \item \textbf{Camera positioning.} Position the virtual camera at $(\phi, \theta)$ on a fixed-radius sphere (0.8\,m) around the target object centroid by computing the look-at rotation matrix analytically and writing it directly to MuJoCo's \texttt{model.body\_pos} and \texttt{model.body\_quat} arrays.

  \item \textbf{Depth rendering and noise injection.} Render the MuJoCo depth buffer at $480 \times 640$ resolution and inject $\mathcal{N}(0, \sigma_d^2)$ noise per pixel; clip to non-negative values.

  \item \textbf{Segmentation.} Render the segmentation buffer to identify which pixels belong to the target object. Compute $C_{pc}$ as the fraction of target pixels.

  \item \textbf{Point cloud generation.} Back-project the noisy depth map to a 3D point cloud using the pinhole camera model; randomly downsample to fraction $\rho$.

  \item \textbf{Grasp synthesis.} Feed the degraded point cloud to Contact-GraspNet and record the top-ranked grasp pose, confidence score $q_{\text{grasp}}$, and total candidate count $n_{\text{grasps}}$.

  \item \textbf{Frame transformation.} Convert the CGN grasp pose from the camera frame (OpenCV convention) to the MuJoCo world frame.

  \item \textbf{Variable measurement.} Compute $e_{\text{pose}}$ as the Euclidean distance between the proposed grasp position and the true object centroid.

  \item \textbf{Grasp execution.} Move the simulated Franka Panda arm to the proposed grasp position using the Damped Least Squares inverse kinematics controller, then close the gripper.

  \item \textbf{Outcome evaluation.} Evaluate binary outcome $Y$ via the proximity criterion.

  \item \textbf{Data logging.} Record $(\sigma_d, \rho, \phi, \theta, C_{pc}, q_{\text{grasp}}, n_{\text{grasps}}, e_{\text{pose}}, Y)$ to CSV.
\end{enumerate}

\section{Camera Positioning and Virtual Viewpoint}
\label{sec:camera_positioning}

The perception camera is mounted on a body (\texttt{perception\_camera\_body}) defined in the MuJoCo scene XML. This body has no mass and does not participate in contact dynamics. At each trial, the body's position and orientation are set programmatically to place the camera at the desired viewpoint on the viewing sphere.

The camera position is computed from the spherical coordinates $(\phi, \theta, r)$ as:
\begin{align}
  x_{\text{cam}} &= x_{\text{obj}} + r \cos\phi \cos\theta, \nonumber \\
  y_{\text{cam}} &= y_{\text{obj}} + r \cos\phi \sin\theta, \label{eq:cam_pos} \\
  z_{\text{cam}} &= z_{\text{obj}} + r \sin\phi, \nonumber
\end{align}
where $(x_{\text{obj}}, y_{\text{obj}}, z_{\text{obj}}) = (0.5, 0, 0.455)$\,m is the target object centroid and $r = 0.8$\,m is the sphere radius.

The camera orientation is computed using a look-at construction. The forward direction is the unit vector from the camera position to the target:
\begin{equation}
  \hat{\mathbf{f}} = \frac{\mathbf{p}_{\text{obj}} - \mathbf{p}_{\text{cam}}}
                         {\|\mathbf{p}_{\text{obj}} - \mathbf{p}_{\text{cam}}\|}.
  \label{eq:forward}
\end{equation}
The right direction is computed as the cross product with the world up vector:
\begin{equation}
  \hat{\mathbf{r}} = \frac{\hat{\mathbf{f}} \times \hat{\mathbf{z}}_{\text{world}}}
                         {\|\hat{\mathbf{f}} \times \hat{\mathbf{z}}_{\text{world}}\|},
  \label{eq:right}
\end{equation}
and the up direction completes the orthonormal frame:
\begin{equation}
  \hat{\mathbf{u}} = \hat{\mathbf{r}} \times \hat{\mathbf{f}}.
  \label{eq:up}
\end{equation}

In MuJoCo, the camera looks along the local $-Z$ axis, with $+X$ pointing right and $+Y$ pointing up. Therefore, the rotation matrix from camera frame to world frame has columns $(\hat{\mathbf{r}}, \hat{\mathbf{u}}, -\hat{\mathbf{f}})$:
\begin{equation}
  \mathbf{R} = \begin{bmatrix} \hat{\mathbf{r}} & \hat{\mathbf{u}} & -\hat{\mathbf{f}} \end{bmatrix}.
  \label{eq:cam_rot}
\end{equation}
This rotation matrix is then converted to a unit quaternion and written to \texttt{model.body\_quat}.

\subsection{Why the Virtual Camera Is Rigorous for Causal Inference}

One might question whether a virtual camera weakens the experimental validity relative to a physical camera. For this study, the opposite is true. A physical camera introduces confounders that are difficult to disentangle: vibration-induced jitter correlates with movement; ambient illumination changes correlate with time of day; cable drag induces systematic orientation drift. Each of these effects would modify the observed depth map in ways that cannot be cleanly attributed to a single causal variable.

The MuJoCo virtual camera eliminates all such confounders by construction. Elevation $\phi$ and azimuth $\theta$ can be set to exact values independently of one another and independently of $\sigma_d$ and $\rho$. This enforces the experimental ideal of varying one factor at a time while holding all others fixed---the foundational requirement of causal identifiability~\cite{pearl2009causality}.

\section{Depth Rendering and Noise Injection}
\label{sec:depth_rendering}

The depth buffer is rendered using MuJoCo's built-in renderer at $480 \times 640$ pixel resolution. The renderer produces a two-dimensional array in which each element stores the perpendicular distance, in metres, from the camera's focal point to the nearest surface visible at that pixel.

Noise injection is implemented as a simple additive operation:
\begin{equation}
  d_{\text{noisy}}(u, v) = \max\!\left(0,\; d_{\text{raw}}(u, v) + \epsilon(u, v)\right),
  \qquad \epsilon(u, v) \sim \mathcal{N}(0, \sigma_d^2),
  \label{eq:noise_injection}
\end{equation}
where the $\max$ operation ensures that depth values remain non-negative. The noise is drawn independently for each pixel and each trial, using a seeded random number generator (\texttt{numpy.random.default\_rng}) to ensure reproducibility.

\section{The Point Cloud as a Geometric Representation}
\label{sec:pointcloud_definition}

\subsection{Formal Definition}

A \emph{point cloud} is the primary input to the Contact-GraspNet grasp synthesis
model and the central perceptual object in this pipeline. It is necessary to define
it precisely, because it is this object whose quality the four causal variables
$(\sigma_d,\, \rho,\, \phi,\, \theta)$ degrade.

\begin{definition}[Point Cloud]
\label{def:pointcloud}
A point cloud $\mathcal{P}$ is a finite, unordered set of vectors in
three-dimensional Euclidean space:
\begin{equation}
  \mathcal{P} = \bigl\{\, \mathbf{p}_i \in \mathbb{R}^3 \;\big|\; i = 1, \ldots, N \,\bigr\},
  \label{eq:pointcloud_def}
\end{equation}
where each element $\mathbf{p}_i = (X_i,\, Y_i,\, Z_i)^\top$ encodes the
three-dimensional Cartesian coordinates of a single surface sample, and $N$ is
the total number of samples.
\end{definition}

Several properties of this definition deserve emphasis.  First, the point cloud
has no inherent topological structure: there are no edges, faces, or connectivity
relations between the points.  Each point is an independent geometric measurement.
Second, the set is unordered: permuting the indices $i$ yields the same point cloud.
This distinguishes a point cloud from an image, where pixel $(u,v)$ has a fixed
neighbourhood.  Third, the point cloud is \emph{partial}: it contains only those
surface locations that are visible from the camera's viewpoint and within the
sensor's measurement range.  Points on occluded or distant surfaces are absent.

This last property is not a deficiency but a physically accurate representation
of what a depth sensor observes from a single viewpoint.  Real-world depth sensors
such as the Intel RealSense D400 series and the Microsoft Kinect produce exactly
this structure: a set of metric surface samples from the sensor's perspective.
The point cloud formalises this.

\subsection{Generation via Pinhole Back-Projection}
\label{sec:backprojection}

In this project, the point cloud is generated by \emph{back-projecting} the
rendered depth image through the pinhole camera model.  The depth buffer
$D \in \mathbb{R}^{H \times W}$ produced by MuJoCo's renderer contains, at each
pixel $(u, v)$, the perpendicular distance $d(u,v)$ in metres from the camera's
focal point to the nearest visible surface.  Only pixels with valid depth
($0 < d(u,v) < d_{\max}$, where $d_{\max}$ is the scene far-clip distance) are
used; background pixels are excluded.

The back-projection recovers the 3D camera-frame coordinates of the surface point
that produced each valid depth measurement.  For a pixel at position $(u, v)$ with
depth value $d = d_{\text{noisy}}(u, v)$ (after noise injection, per
Equation~\eqref{eq:noise_injection}), the 3D coordinates in the camera frame are:
\begin{equation}
  X^{(\text{cam})} = \frac{(u - c_x)\, d}{f_x}, \qquad
  Y^{(\text{cam})} = \frac{(v - c_y)\, d}{f_y}, \qquad
  Z^{(\text{cam})} = d,
  \label{eq:backproject}
\end{equation}
where $(f_x, f_y)$ are the focal lengths in pixels and $(c_x, c_y)$ is the
principal point (image centre).  The focal lengths are computed analytically from
the MuJoCo vertical field-of-view $\alpha$ and image height $H$:
\begin{equation}
  f_y = \frac{H/2}{\tan(\alpha/2)}, \qquad f_x = f_y
  \label{eq:focal_from_fov}
\end{equation}
(square pixels are assumed, as MuJoCo renders with equal horizontal and vertical
angular resolution).  For the 60° vertical FOV and $H = 480$ pixels used in
this project, $f_y \approx 415.7$\,px.

The set of all such back-projected vectors, collected over valid pixels, constitutes
the point cloud in the camera frame.  These points are then rotated and translated
into the world frame using the camera's pose $(R_{\text{cam}}, \mathbf{t}_{\text{cam}})$:
\begin{equation}
  \mathbf{p}_i = R_{\text{cam}}\, \mathbf{p}_i^{(\text{cam})} + \mathbf{t}_{\text{cam}}.
  \label{eq:world_frame_points}
\end{equation}
The resulting set $\mathcal{P} = \{\mathbf{p}_1, \ldots, \mathbf{p}_N\}$ is the
world-frame point cloud that is passed to Contact-GraspNet.

\subsection{Why the Point Cloud Is the Correct Representation for This Pipeline}
\label{sec:pointcloud_justification}

The choice of a point cloud as the perceptual representation---rather than the
raw depth image, a voxel grid, or a reconstructed mesh---is not arbitrary.  It
is dictated by three considerations that together make it the uniquely appropriate
choice for this study.

\textbf{CGN's architecture requires a point cloud input.}
Contact-GraspNet~\cite{sundermeyer2021contact} operates directly on the elements
of $\mathcal{P}$.  Its architecture processes each point $\mathbf{p}_i$ through a
PointNet++-style encoder~\cite{qi2017pointnetpp} that aggregates local geometric
features by grouping neighbouring points in 3D space.  For each point, the network
then predicts whether it is a valid contact point for a parallel-jaw gripper and,
if so, what the associated grasp pose should be.  This contact-centric formulation
is architecturally anchored to the point cloud: the network's prediction heads
are defined \emph{per point in $\mathcal{P}$}, not per image pixel or per voxel.
Providing the raw depth image or a mesh instead would require a fundamentally
different model.  Using the point cloud is therefore not a design choice made in
this thesis but a prerequisite of using CGN.

\textbf{Partial observability is physically realistic.}
CGN was trained on partial point clouds generated from single-viewpoint depth
renders of ShapeNet objects~\cite{sundermeyer2021contact}---precisely the same
modality as the perception pipeline in this thesis.  A full mesh or a CAD model
of the target object would be \emph{out of distribution} for CGN: the network has
never been trained to process complete, noise-free geometric representations.
Using the partial, viewpoint-dependent point cloud produced by back-projection
faithfully reproduces the input distribution on which CGN was trained, which is
essential for the validity of any degradation study.  A degradation that pushes
the input away from the training distribution for a reason unrelated to the
variable under study would confound the causal analysis.

\textbf{Causal perturbations are cleanly separable on the point cloud.}
The four causal variables in this study act on the point cloud through distinct
and non-interacting mechanisms, which is the condition required for causal
identifiability~\cite{pearl2009causality}:
\begin{itemize}
  \item Depth noise $\sigma_d$ perturbs the $Z_i$ coordinate (and propagates
        proportionally to $X_i$ and $Y_i$ through the back-projection
        equations~\eqref{eq:backproject}), independently across points and trials.
  \item Sparsity $\rho$ removes a random fraction $(1 - \rho)$ of points from the
        set $\mathcal{P}$, reducing $N$ without affecting the coordinates of
        retained points.
  \item Camera elevation $\phi$ and azimuth $\theta$ determine which surface regions
        are visible from the viewpoint, controlling which surface locations can
        appear in $\mathcal{P}$ at all, prior to any noise or downsampling.
\end{itemize}
These operations cannot be cleanly separated on a depth image (which is a
structured 2D grid with implicit coordinate geometry), a voxel grid (where
sparsity would mean empty cells rather than missing surface samples), or a mesh
(where connectivity would be disrupted by point removal).  On the point cloud,
each operation is a well-defined algebraic transformation on $\mathcal{P}$.

\subsection{Formal Definition of the Downsampled Point Cloud}
\label{sec:pointcloud_downsampling}

Sparsity is operationalised as uniform random subsampling.  Let $\mathcal{P}$
denote the full back-projected point cloud with $N$ points.  The downsampled
cloud $\mathcal{P}_\rho$ is defined as:
\begin{equation}
  \mathcal{P}_\rho = \bigl\{\, \mathbf{p}_i \;\big|\; i \in \mathcal{I}_\rho \,\bigr\},
  \qquad
  \mathcal{I}_\rho \sim \operatorname{Uniform}\!\left(\binom{[N]}{\lceil \rho N \rceil}\right),
  \label{eq:downsampled_cloud}
\end{equation}
where $\mathcal{I}_\rho$ is a random subset of $\lceil \rho N \rceil$ indices
drawn uniformly without replacement from $\{1, \ldots, N\}$.  This preserves the
statistical character of the original point cloud (no spatial bias is introduced)
while reducing the number of surface samples available to CGN.  In code, this is
implemented via \texttt{numpy.random.Generator.choice} without replacement, using
a seeded generator for reproducibility.

The point cloud $\mathcal{P}_\rho$ is the final output of the perception stage and
the direct input to Contact-GraspNet.  Its cardinality $|\mathcal{P}_\rho| = \lceil \rho N \rceil$
ranges from the full cloud ($\rho = 1.0$) to 25\% of the original points ($\rho = 0.25$),
with $\rho \in \{1.0, 0.75, 0.50, 0.25\}$ across the experimental grid.

\section{Coordinate Frame Transformation}
\label{sec:frame_transform}

The camera intrinsics used in the back-projection (Equation~\eqref{eq:backproject}) are
derived analytically from MuJoCo's vertical field-of-view parameter, as given in
Equation~\eqref{eq:focal_from_fov}.  The downsampled point cloud $\mathcal{P}_\rho$
(Definition~\eqref{eq:downsampled_cloud}) is then passed to Contact-GraspNet, which
outputs grasp poses in the camera frame.

Contact-GraspNet outputs grasp poses in the camera's local frame following the OpenCV convention: $+Z$ forward (into the scene), $+Y$ downward, $+X$ rightward. MuJoCo's camera convention follows OpenGL: $+Z$ backward (out of the scene), $+Y$ upward. Conversion between the two conventions requires negating the $Y$ and $Z$ axes:
\begin{equation}
  \mathbf{F} = \operatorname{diag}(1,\, -1,\, -1).
  \label{eq:flip}
\end{equation}

Let $\mathbf{T} \in \mathbb{R}^{4 \times 4}$ be the homogeneous camera-to-world transform obtained from MuJoCo's \texttt{data.cam\_xmat} (the $3 \times 3$ rotation matrix stored column-major in a flat array of length 9) and \texttt{data.cam\_xpos} (the $3 \times 1$ position vector). A grasp pose $\mathbf{P}_{\text{cam}}$ in the OpenCV camera frame is transformed to the world frame as:
\begin{equation}
  \mathbf{P}_{\text{world}} = \mathbf{T} \, \mathbf{F} \, \mathbf{P}_{\text{cam}}.
  \label{eq:transform}
\end{equation}
The translation component $\mathbf{P}_{\text{world}}[:3, 3]$ gives the proposed gripper position in world coordinates, from which $e_{\text{pose}}$ is computed as the Euclidean distance to the true object centroid.

The implementation of this transformation is shown in the following code snippet:

\begin{lstlisting}[caption={Camera-to-world frame transformation.},label={lst:cam_to_world}]
def cam_to_world(pose_cam, model, data):
    cam_id  = mujoco.mj_name2id(model,
                 mujoco.mjtObj.mjOBJ_CAMERA, CAM_NAME)
    cam_rot = data.cam_xmat[cam_id].reshape(3, 3)
    cam_pos = data.cam_xpos[cam_id]
    flip    = np.diag([1., -1., -1.])
    T       = np.eye(4)
    T[:3, :3] = cam_rot
    T[:3,  3] = cam_pos
    F         = np.eye(4)
    F[:3, :3] = flip
    return T @ F @ pose_cam
\end{lstlisting}

\section{Inverse Kinematics Controller}
\label{sec:ik_controller}

After the grasp position is obtained in world coordinates, an automated control pipeline moves the simulated Franka Panda arm to that position. No human operator intervenes: the physics simulation is stepped forward programmatically, with joint torques computed and applied at each timestep by the controller.

\subsection{Damped Least Squares Method}

The arm is controlled via the Damped Least Squares~(DLS) Jacobian inverse kinematics method~\cite{nakamura1986inverse}. This is an iterative method that computes, at each timestep, a joint velocity increment that moves the end-effector toward the target position while avoiding the singularity problems that plague the standard pseudoinverse method.

At each iteration, MuJoCo's \texttt{mj\_jacSite} function computes the $3 \times n_v$ translational Jacobian $\mathbf{J}$ at the end-effector site, where $n_v = 15$ is the total number of velocity degrees of freedom in the scene. The columns of the full Jacobian correspond to all velocity DoFs:
\begin{itemize}
  \item Columns 0--5: the free joint of the target object (3 linear + 3 angular velocity DoFs).
  \item Columns 6--12: the 7 arm joint velocities.
  \item Columns 13--14: the 2 finger joint velocities.
\end{itemize}

Only the arm columns $\mathbf{J}_{\text{arm}} = \mathbf{J}[:, 6{:}13]$ are extracted, yielding a $3 \times 7$ matrix. The joint velocity increment is then computed as:
\begin{equation}
  \Delta\mathbf{q} = \mathbf{J}_{\text{arm}}^{\top}
    \left(\mathbf{J}_{\text{arm}} \mathbf{J}_{\text{arm}}^{\top}
    + \lambda^2 \mathbf{I}\right)^{-1} \mathbf{e},
  \label{eq:dls}
\end{equation}
where $\mathbf{e} = \mathbf{p}_{\text{target}} - \mathbf{p}_{\text{ee}}$ is the position error (a $3 \times 1$ vector), $\lambda = 0.01$ is the damping factor, and $\mathbf{I}$ is the $3 \times 3$ identity matrix.

\subsection{Derivation of the DLS Formula}

The standard inverse kinematics problem seeks a joint velocity $\dot{\mathbf{q}}$ such that:
\begin{equation}
  \mathbf{J} \dot{\mathbf{q}} = \mathbf{e}.
\end{equation}
When $\mathbf{J}$ is not square or is near-singular, the pseudoinverse solution $\dot{\mathbf{q}} = \mathbf{J}^{\dagger} \mathbf{e}$ produces unbounded joint velocities near singularities. The DLS method regularises this by solving instead the optimisation problem:
\begin{equation}
  \min_{\dot{\mathbf{q}}} \|\mathbf{J} \dot{\mathbf{q}} - \mathbf{e}\|^2
  + \lambda^2 \|\dot{\mathbf{q}}\|^2.
\end{equation}
Taking the derivative with respect to $\dot{\mathbf{q}}$ and setting it to zero:
\begin{align}
  2 \mathbf{J}^{\top}(\mathbf{J} \dot{\mathbf{q}} - \mathbf{e})
  + 2\lambda^2 \dot{\mathbf{q}} &= \mathbf{0}, \nonumber \\
  (\mathbf{J}^{\top}\mathbf{J} + \lambda^2 \mathbf{I}) \dot{\mathbf{q}}
  &= \mathbf{J}^{\top} \mathbf{e}.
\end{align}
Using the identity $\mathbf{J}^{\top}(\mathbf{J}\mathbf{J}^{\top} + \lambda^2\mathbf{I})^{-1} = (\mathbf{J}^{\top}\mathbf{J} + \lambda^2\mathbf{I})^{-1}\mathbf{J}^{\top}$, we arrive at the form used in the implementation:
\begin{equation}
  \dot{\mathbf{q}} = \mathbf{J}^{\top}
    (\mathbf{J}\mathbf{J}^{\top} + \lambda^2\mathbf{I})^{-1} \mathbf{e}.
\end{equation}
The $3 \times 3$ matrix $\mathbf{J}\mathbf{J}^{\top} + \lambda^2\mathbf{I}$ is always invertible (the damping ensures positive definiteness), and its inversion is computationally inexpensive because it is only $3 \times 3$.

\subsection{Control Loop Mechanics}
\label{sec:control_loop}

Understanding how the arm physically moves in the simulation requires understanding the interaction between the IK controller and MuJoCo's physics engine. The sequence at each IK iteration is:

\begin{enumerate}
  \item \texttt{mj\_forward(model, data)} is called to compute the current kinematics (site positions, Jacobians) from the current joint positions.

  \item The position error $\mathbf{e}$ is computed between the target and the current end-effector position.

  \item The Jacobian is computed at the end-effector site using \texttt{mj\_jacSite}.

  \item The DLS formula (Equation~\ref{eq:dls}) computes the joint velocity increment $\Delta\mathbf{q}$.

  \item The increment is scaled by a factor $\alpha = \min(0.5, 0.1 / (\|\Delta\mathbf{q}\| + 10^{-8}))$ to prevent large jumps. This adaptive scaling ensures that the step size is at most 0.1 radians when the error is large and up to 0.5 radians when the error is small.

  \item The scaled increment is added to the current joint positions: $\texttt{data.qpos[7:14]} \mathrel{+}= \Delta\mathbf{q} \cdot \alpha$.

  \item The updated joint positions are clipped to the joint limits defined in the MuJoCo model.

  \item The joint positions are mirrored to the control vector: $\texttt{data.ctrl[0:7]} = \texttt{data.qpos[7:14]}$. This is critical because the MuJoCo actuators are position controllers: they compare the control target (\texttt{ctrl}) with the current joint position (\texttt{qpos}) and generate torques proportional to the error. By setting \texttt{ctrl} equal to the desired \texttt{qpos}, we command the actuators to maintain the configuration that the IK has computed.

  \item \texttt{mj\_step(model, data)} advances the physics simulation by one timestep (0.002\,s). During this step, MuJoCo's PD actuators generate joint torques based on the difference between \texttt{ctrl} and the actual joint positions, and the equations of motion are integrated to update positions and velocities.
\end{enumerate}

This closed-loop process repeats for up to 2000 iterations (4 seconds of simulated time) or until the position error falls below the tolerance threshold (0.010\,m for the batch experiments).

\section{Grasp Execution Sequence}
\label{sec:grasp_execution}

The full grasp execution for each trial consists of four phases:

\begin{enumerate}
  \item \textbf{Pre-grasp approach.} The arm moves to a position 18\,cm above the CGN-proposed $(x, y)$ position, at a height $z = z_{\text{cylinder}} + 0.18$\,m. This places the end-effector above the object with clearance. The IK controller runs for up to 2000 steps.

  \item \textbf{Descent.} The arm descends from the pre-grasp position to the grasp position at $z = z_{\text{cylinder}} + 0.02$\,m, directly above (or near) the cylinder surface. The IK controller runs for up to 1000 steps with a slightly relaxed tolerance of 0.015\,m.

  \item \textbf{Gripper closure.} The gripper is closed by ramping \texttt{ctrl[7]} (the tendon actuator command) from 255 (fully open) to 0 (fully closed) over 300 simulation steps. The ramp is linear: at each step, $\texttt{ctrl[7]} = \max(0, \texttt{ctrl[7]} - 1.0)$.

  \item \textbf{Outcome evaluation.} After the gripper has closed, the horizontal distance between the end-effector and the true object centroid is measured and compared to the proximity threshold $D_\tau$.
\end{enumerate}

\section{Grasp Success Criterion}
\label{sec:success_criterion_detail}

A full rigid-body grasping pipeline would require the gripper fingers to close around the object with sufficient normal force to overcome gravity during a lift. Tuning the contact stiffness, friction coefficients, and actuator gains to achieve this reliably across 432 headless trials proved impractical with the primitive-shape gripper model used in this project. The challenges involved are discussed in detail in Chapter~\ref{ch:implementation}.

Instead, grasp success is operationalised as a proximity criterion:
\begin{equation}
  Y = \mathbf{1}\!\left[
    \|p_{\text{ee}}^{xy} - p_{\text{obj}}^{xy}\|_2 < D_\tau
  \right],
  \label{eq:success}
\end{equation}
where $p_{\text{ee}}^{xy}$ and $p_{\text{obj}}^{xy}$ are the $(x, y)$ projections of the end-effector and object positions, respectively, and $D_\tau = 0.065$\,m is the calibrated proximity threshold.

\subsection{Threshold Calibration}

The threshold $D_\tau = 0.065$\,m was calibrated to satisfy two constraints simultaneously:

\begin{enumerate}
  \item Under clean conditions ($\sigma_d = 0$, $\rho = 1.0$), the success rate should be approximately 85\%. This allows for the systematic lateral bias that CGN exhibits at certain viewpoints while still indicating that clean perception leads to reliable grasping.

  \item Under maximum degradation ($\sigma_d = 0.04$, $\rho = 0.25$), the success rate should be approximately 0\%. This ensures that severe perceptual degradation produces clear failure, validating the causal claim that degraded perception causes grasp failure.
\end{enumerate}

The threshold is larger than the cylinder radius (0.036\,m) to account for the systematic lateral bias that Contact-GraspNet exhibits at low camera elevations ($\phi = 30°$): the network consistently proposes positions approximately 6\,cm from the true centroid at this angle, even with clean inputs. This bias is a property of CGN's training distribution rather than a perception error introduced by the experimental perturbations. The threshold value still cleanly rejects high-noise cases where $e_{\text{pose}} > 0.10$\,m.

\subsection{Causal Validity of the Proximity Criterion}

This criterion directly operationalises the thesis's causal claim: degraded perception causes the CGN-proposed $(x, y)$ position to drift away from the true cylinder centroid, so the end-effector misses the object. Clean perception keeps $e_{\text{pose}}$ small, the arm centres over the cylinder, and the outcome is success. The criterion measures precisely the quantity that the SCM models: whether the perception-derived grasp position is close enough to the object to enable contact.

\section{SCM Fitting}
\label{sec:scm_fitting}

The coefficients in Equations~\eqref{eq:cpc}--\eqref{eq:ep} are estimated by ordinary least squares (OLS) on the training split of the collected dataset. For each structural equation, the OLS estimator minimises the sum of squared residuals:
\begin{equation}
  \hat{\boldsymbol{\beta}} = (\mathbf{X}^{\top}\mathbf{X})^{-1} \mathbf{X}^{\top} \mathbf{y},
\end{equation}
where $\mathbf{X}$ is the design matrix (the values of the parent variables across all training trials) and $\mathbf{y}$ is the vector of observed values of the dependent variable.

The outcome model (Equation~\ref{eq:Y}) is fitted by logistic regression using maximum likelihood estimation. No neural network training is required for any component of the SCM.

\paragraph{The fitted SCM is a surrogate, not the true mechanism.} It is important to be explicit about what Equations~\eqref{eq:cpc}--\eqref{eq:Y} actually represent. The true data-generating mechanism connecting $(\sigma_d, \rho, \phi, \theta)$ to $Y$ is the composite of the MuJoCo renderer, the segmentation and back-projection pipeline, Contact-GraspNet (a neural network with no closed-form input--output mapping), the damped-least-squares IK controller, and the proximity success criterion. This composite mechanism is not itself a hand-specifiable structural equation---in particular, no one will write down CGN's point-cloud-to-grasp-pose mapping as an explicit $f_i(\text{pa}(V_i), U_i)$. Following Rubenstein et al.~\cite{rubenstein2017consistency}, the fitted linear-logistic model should therefore be understood as a \emph{surrogate} SCM: a lower-fidelity structural model, fitted to the trial data, that approximates the true mechanism's input--output behaviour but does not have equal expressive power. This framing matters because surrogate SCMs of this kind are generally advanced as being sufficient to answer $\mathcal{L}_1$ and $\mathcal{L}_2$ queries (associational and interventional). This thesis pushes the surrogate further, to $\mathcal{L}_3$ counterfactual queries (Section~\ref{sec:counterfactual_diagnosis}), which is a stronger demand: the abduction step inverts the fitted equations to recover per-trial noise terms, and any misspecification in the surrogate's functional form is amplified rather than averaged out by this inversion. We return to this point when interpreting the multi-causal attribution results in Section~\ref{sec:limitations}.

\section{Counterfactual Diagnosis Procedure}
\label{sec:counterfactual_diagnosis}

Before presenting the mechanics of the procedure, it is useful to state its target query explicitly, in potential-outcome notation, so that \emph{what} is being estimated is fixed before describing \emph{how}. For an observed failed trial with conditions $\mathbf{x}^*$ and outcome $Y^* = 0$, and for each exogenous variable $v \in \{\sigma_d, \rho, \phi, \theta\}$, the target is
\begin{equation}
  \tau_v \;=\; P\big(Y(v_{\text{nom}}) = 1 \;\big|\; \mathbf{x}^*, \, Y^* = 0\big),
  \label{eq:target_query}
\end{equation}
where $Y(v_{\text{nom}})$ denotes the potential outcome had variable $v$ been set to its nominal (clean-baseline) value, with all other observed conditions and the abducted noise held fixed. This is precisely the \emph{effect of treatment on the treated} (ETT) estimand~\cite{yang2025hierarchy}: a population-level intervention ($v \to v_{\text{nom}}$) evaluated on the sub-population that is, by definition, restricted to units observed to have failed under their actual treatment. Equation~\eqref{eq:target_query} is an $\mathcal{L}_3$ quantity---it conditions on a specific realised outcome $Y^*$, which distinguishes it from the purely interventional ($\mathcal{L}_2$) quantity $P(Y \mid \doop(v = v_{\text{nom}}))$ that a Causal Bayesian Network alone could supply. Answering it for every $v$ and ranking the resulting $\tau_v$ is the task that Algorithm~\ref{alg:diagnosis} performs.

The counterfactual diagnosis procedure is formalised in Algorithm~\ref{alg:diagnosis}. For each failure case, the procedure computes a ranked attribution over the four exogenous variables.

\paragraph{What abduction does and does not do here.} It is important to be explicit about the epistemic status of the abduction step in this setting, rather than let the three-step label imply more inference than actually takes place. Because every trial's exogenous conditions $\mathbf{x}^* = (\sigma_d^*, \rho^*, \phi^*, \theta^*)$ are set and logged directly by the experimenter under full factorial control, abduction in this thesis never infers the exogenous variables themselves---there is nothing hidden about them to recover. What abduction does recover is the set of per-trial exogenous \emph{noise terms} of the intermediate structural equations ($U_C, U_q, U_n, U_e$ in Equations~\eqref{eq:cpc}--\eqref{eq:ep}), which are not directly observed and must be solved for given the observed intermediates. Under full experimental control, therefore, the abduction step is closer to bookkeeping than to genuine inference: the diagnostic work that actually discriminates between candidate root causes is carried out by the action and prediction steps, which ask what would have happened under a counterfactual reset of an already-known exogenous variable. A setting in which abduction did real epistemic work would instead hide the true $(\sigma_d, \rho, \phi, \theta)$ from the diagnostic system and require them to be inferred from the intermediate variables ($C_{pc}, q_{\text{grasp}}, n_{\text{grasps}}, e_{\text{pose}}$) alone, before the action and prediction steps could proceed. Section~\ref{sec:future_work} identifies this partial-observability variant as the highest-priority methodological extension of the present procedure; in its absence, Algorithm~\ref{alg:diagnosis} should be read as validating the action-prediction machinery under known exogenous conditions, not as a demonstration of abductive inference under uncertainty.

\begin{algorithm}[t]
\caption{SCM Counterfactual Failure Diagnosis}
\label{alg:diagnosis}
\begin{algorithmic}[1]
\Require Observed conditions $\mathbf{x}^* = (\sigma_d^*, \rho^*, \phi^*, \theta^*)$, observed intermediates $(C_{pc}^*, q^*, e^*)$, failed outcome $Y^* = 0$, fitted SCM
\Ensure Ranked attribution $\{(v_i, \Delta_i)\}$
\State \textbf{Abduction:} solve for noise terms $U_C, U_q, U_e$ consistent with $(C_{pc}^*, q^*, e^*)$ under $\mathbf{x}^*$
\For{each variable $v \in \{\sigma_d, \rho, \phi, \theta\}$}
  \State \textbf{Action:} set $v \leftarrow v_{\text{nominal}}$, hold all others at $\mathbf{x}^*$
  \State \textbf{Prediction:} propagate through SCM with abducted noise; compute $\hat{P}(Y{=}1)$
  \State $\Delta_v \leftarrow \hat{P}(Y{=}1) - P_{\text{obs}}$
\EndFor
\State $v^* \leftarrow \arg\max_v \Delta_v$
\State \Return ranked list $(v_i, \Delta_i)$ sorted by $\Delta$ descending
\end{algorithmic}
\end{algorithm}

The variable $v^*$ with the largest counterfactual improvement $\Delta_v$ is identified as the most likely root cause of the failure under the model, and $\Delta_v$ is precisely the estimate of $\tau_v$ from Equation~\eqref{eq:target_query} produced by the abduction--action--prediction procedure. The ``nominal'' values represent clean or baseline conditions: $\sigma_d = 0$, $\rho = 1.0$, $\phi = 45°$, $\theta = 0°$.

Identifiability of Equation~\eqref{eq:target_query} from the abduction step (Eq.~\ref{eq:abduction}) requires an assumption on the exogenous noise terms $U_C, U_q, U_n, U_e$ that has not yet been made explicit: the abduction step solves for each $U_i$ \emph{independently}, from its own structural equation alone, and then reuses all of them jointly in the prediction step. This is only valid if the noise terms are mutually independent---that is, if the SCM is a non-parametric structural equation model with independent errors (NPSEM-ie), rather than the more general SCM in which errors may be dependent~\cite{vonk2023disentangling}. This assumption is not automatic: Richardson and Robins~\cite{richardsonrobins2013} have argued at length that NPSEM-ie independence is a substantive, empirically untestable commitment that is frequently adopted implicitly and should instead be stated and defended on a case-by-case basis. We therefore state it explicitly here rather than leaving it implicit in the phrase ``the SCM is Markovian.''

We adopt the NPSEM-ie assumption, and we defend it on mechanistic grounds specific to this pipeline rather than as a generic simplification. The four noise terms arise from distinct, physically separated stages of the pipeline: $U_C$ reflects segmentation-buffer discretisation and is computed before any noise or downsampling is applied; $U_q$ reflects Contact-GraspNet's internal scoring stochasticity for the top-ranked grasp; $U_n$ reflects the discreteness of the candidate-counting process; and $U_e$ reflects error in a separate pose-regression head of the same network. These four sources of unmodelled variation do not share a common upstream mechanism once the parent variables $(\sigma_d, \rho, \phi, \theta, C_{pc})$ are conditioned on---each is generated by a different computational stage (rendering, segmentation, or a different output head of CGN) that does not read the others' internal state. This is a design-specific argument, not a universal property of SCMs, and it is offered as a justification rather than a proof: a residual correlation analysis of the fitted noise terms (e.g.\ pairwise correlation of OLS residuals across $C_{pc}, q_{\text{grasp}}, n_{\text{grasps}}, e_{\text{pose}}$) would strengthen this claim empirically and is noted as a direct check for future work.

Note that selecting $\arg\max_v \Delta_v$ identifies the variable with the \emph{largest} counterfactual impact, which is a sufficient but not minimal notion of causation. The stricter Halpern--Pearl definition of actual causation~\cite{halpern2005causes} additionally requires minimality and normality conditions that are not checked here; this is left for future work.

\section{LLM Comparison Baseline}
\label{sec:llm_baseline}

A vision-language model (Gemini~2.5~Flash) is prompted with a structured description of each
failed trial and asked to identify the most likely root cause from the closed set
$\{\sigma_d,\,\rho,\,\phi,\,\theta,\,\texttt{joint},\,\texttt{none}\}$.
This is a \emph{closed-set classification} task: the candidate variables are named in the
prompt. ``Zero-shot'' here means no task-specific fine-tuning or in-context examples were
provided---not open-vocabulary diagnosis.

To prevent information leakage, the LLM is \emph{not} given the numerical values of the
exogenous ground-truth variables (e.g., $\sigma_d = 0.04$\,m). Information is provided
across three observation-depth tiers of increasing richness:

\begin{description}
  \item[Tier~1 (T1 --- inputs only).] The LLM receives only the fact of failure and the
    names and qualitative descriptions of the four candidate variables. No camera
    configuration is disclosed.
  \item[Tier~2 (T2 --- \textrm{+}camera configuration).] T1 information plus qualitative
    camera placement (e.g.\ ``elevation: overhead~$\approx$60\textdegree$''$,
    ``azimuth: side~$\approx$45\textdegree$''$). This is the first tier that reveals any
    exogenous-variable information.
  \item[Tier~3 (T3 --- \textrm{+}perception metrics).] T2 information plus the full
    perception and grasp-quality pipeline outputs: $C_{pc}$, $n_{\text{grasps}}$,
    $q_{\text{grasp}}$, and $e_{\text{pose}}$.
\end{description}

To ensure a rigorous, bias-free comparison, the following protocol was pre-registered before
any API calls were made:

\begin{itemize}
  \item The prompt template and six-code response format are fixed before any LLM trials
    are run. The \texttt{joint} code is required because 57.2\,\% of the 292 failures
    (167 trials) have no single-variable fix; the \texttt{none} code captures irreducible
    failures.
  \item The scoring rubric (Table~\ref{tab:llm_rubric}) is defined before evaluation begins
    and uses strict exact-match: \texttt{none} ground truth accepts only \texttt{none}
    (not \texttt{joint}), preventing the degenerate ``always say joint'' strategy
    (which would score 67.5\,\% under a lenient rule) from inflating apparent accuracy.
  \item \textbf{Primary comparison scope} (both SCM and LLM evaluated): the 95
    single-variable-fixable trials ($\sigma_d$=36, $\theta$=35, $\phi$=23, $\rho$=1).
    On these trials the SCM's $\arg\max_v \Delta_v$ attribution and the LLM attribution
    are comparable under the same exact-match rule.
  \item \textbf{Secondary metric} (LLM only): all 292 failed trials. The LLM is also
    evaluated on multi-causal and irreducible failures, against a majority-class baseline
    of 57.2\,\% (always predict \texttt{none}).
  \item Consistency is measured by three stochastic calls at $T=1.0$ per trial; the
    agreement rate is the fraction of the three calls matching the modal attribution.
    A fourth deterministic call at $T=0.0$ provides the scored attribution and is
    not counted in the consistency set.
  \item The $\rho$ category ($n=1$ trial) is reported separately in all tables and is
    not aggregated with other single-variable categories.
\end{itemize}

\chapter{Implementation and Development}
\label{ch:implementation}

This chapter documents the implementation process in detail, including the construction of the simulation environment, the iterative development of the control pipeline, and the critical bugs that were encountered and resolved. The goal is to provide an honest account of the engineering challenges involved in building a working simulation-to-inference pipeline, as these challenges significantly influenced the final experimental design.

\section{Simulation Environment Construction}
\label{sec:sim_construction}

\subsection{The Mesh Unavailability Problem}

The Franka Emika Panda arm model available in MuJoCo Menagerie~\cite{menagerie2022} is the standard reference model for simulation research involving this robot. However, the Menagerie distribution uses Git Large File Storage~(LFS) for the detailed mesh assets (\texttt{.stl} files) that define the visual and collision geometry of each link. In the development environment used for this project, Git LFS was not available, which meant that the mesh files could not be downloaded. Attempting to load the Menagerie \texttt{panda.xml} without the mesh files resulted in an immediate parsing error from MuJoCo.

This necessitated a complete reconstruction of the Panda arm using MuJoCo's built-in primitive shapes: capsules, boxes, and cylinders. The kinematic chain---the positions, orientations, and axis definitions of all seven revolute joints---was transcribed exactly from the Menagerie \texttt{panda.xml}. The inertial properties (mass, centre of mass, and diagonal inertia tensors) for each link were also preserved exactly. Only the visual and collision geometry was changed: each link's detailed mesh was replaced by one or two capsule primitives with dimensions chosen to approximately envelop the real link geometry.

\subsection{Scene Structure}

The resulting scene file (\texttt{grasp\_scene\_v2.xml}) contains the following elements:

\begin{enumerate}
  \item \textbf{Ground plane and table.} A flat ground plane and a table modelled as a box body at position $(0.5, 0, 0.2)$\,m with half-extents $(0.3, 0.4, 0.2)$\,m, giving a 40\,cm-tall table surface.

  \item \textbf{Target object.} A cylinder (radius 0.036\,m, half-height 0.055\,m) placed at $(0.5, 0, 0.455)$\,m, i.e., on top of the table with its centre 5.5\,cm above the table surface. The cylinder is connected to the world via a free joint, giving it 6 degrees of freedom for translation and rotation. The mass is set to 0.05\,kg (light enough for the simplified gripper to support) with high friction ($\mu = 2.5$).

  \item \textbf{Panda arm.} Seven revolute joints (\texttt{joint1}--\texttt{joint7}) with the exact DH-compatible positions and orientations from the Menagerie model. Each joint has armature (0.1) and damping (1.0) parameters. The hand body is positioned at $z = 0.107$\,m above the flange with a $22.5°$ yaw offset (implemented as a quaternion rotation). Two prismatic finger joints slide along the hand's local $Y$-axis with range $[0, 0.04]$\,m.

  \item \textbf{Actuators.} Seven position-controlled actuators for the arm joints, implemented as MuJoCo ``general'' actuators with gains and biases matching the Menagerie model (e.g., joint 1: gain = 4500, bias = $[0, -4500, -450]$). An eighth actuator controls the gripper via a tendon coupling the two finger joints, with control range $[0, 255]$ (255 = open, 0 = closed).

  \item \textbf{Perception camera.} A massless body (\texttt{perception\_camera\_body}) at a default position, containing a camera with 45° vertical field of view. The body has a small box geom for visualisation but with \texttt{contype=0} and \texttt{conaffinity=0} so it does not participate in collision detection.

  \item \textbf{Home keyframe.} A keyframe that sets the initial joint configuration to the standard Panda home pose: $[0, 0, 0, -\pi/2, 0, \pi/2, -\pi/4]$ for the arm joints, with fingers fully open (0.04\,m each) and the gripper control set to 255.
\end{enumerate}

\subsection{Gripper Geometry: Visual Meshes vs Collision Primitives}
\label{sec:gripper_geometry}

A notable difference exists between the high-fidelity visual representation of the Panda gripper often seen in robotics simulations and the gripper geometry used in this experiment's active physics scene (\texttt{grasp\_scene\_v2.xml}). 

When first loading the Panda arm from MuJoCo Menagerie, the end-effector is typically rendered using complex visual meshes provided by the manufacturer. While visually appealing, these complex non-convex meshes pose significant challenges for physics engines during contact resolution. Calculating penetrations and friction forces between complex meshes and target objects can lead to non-deterministic bouncing, interpenetration, or simulation instability---particularly critical flaws for an automated 432-trial causal study requiring precise reproducibility.

To ensure stable, fast, and deterministic contact dynamics, the simulation environment was rebuilt using simplified collision primitives (capsules and boxes) for the robot's links and gripper fingers. This is a standard optimization in reinforcement learning and manipulation research. The causal inference framework in this thesis focuses on the effect of perception degradation on the proposed 6-DoF grasp pose (the inverse kinematics target); the simplified collision geometry ensures that when the arm reaches the proposed target, the subsequent physical interaction is mathematically robust.

\subsection{qpos Layout}

A critical implementation detail is the layout of MuJoCo's generalised position vector \texttt{data.qpos}. Because the target object has a free joint that appears before the arm joints in the XML body hierarchy, the \texttt{qpos} array has the following layout (total: $n_q = 16$):

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Indices} & \textbf{Count} & \textbf{Description} \\
\midrule
\texttt{qpos[0:3]}  & 3 & Free joint translation $(x, y, z)$ \\
\texttt{qpos[3:7]}  & 4 & Free joint orientation $(q_w, q_x, q_y, q_z)$ \\
\texttt{qpos[7:14]} & 7 & Arm joint angles (joints 1--7) \\
\texttt{qpos[14:16]} & 2 & Finger joint positions \\
\bottomrule
\end{tabular}
\end{center}

Similarly, the velocity vector \texttt{data.qvel} has $n_v = 15$ elements (the free joint contributes 6 velocity DoFs rather than 7 position DoFs because orientation velocity is parameterised as a 3D angular velocity vector rather than a 4D quaternion derivative):

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Indices} & \textbf{Count} & \textbf{Description} \\
\midrule
\texttt{qvel[0:3]}  & 3 & Free joint linear velocity \\
\texttt{qvel[3:6]}  & 3 & Free joint angular velocity \\
\texttt{qvel[6:13]} & 7 & Arm joint velocities \\
\texttt{qvel[13:15]} & 2 & Finger joint velocities \\
\bottomrule
\end{tabular}
\end{center}

This distinction between $n_q$ and $n_v$ is important because the Jacobian has $n_v$ columns (one per velocity DoF), not $n_q$. The IK controller must extract columns 6--12 of the Jacobian (corresponding to the arm joint velocities) but write the computed increments to \texttt{qpos[7:14]} (the arm joint positions). Confusing these two index ranges was the source of a critical bug described in Section~\ref{sec:bug_teleportation}.

\section{Critical Bugs Encountered and Resolved}
\label{sec:bugs}

The development process involved several critical bugs that significantly impacted the project timeline. Each bug is described here with its symptoms, root cause, and resolution, to serve as a reference for future work with MuJoCo-based simulation pipelines.

\subsection{Bug 1: Object Teleportation}
\label{sec:bug_teleportation}

\textbf{Symptoms.} During early testing of the IK controller, the target cylinder would spontaneously fly off the table and fall through the floor. The arm joints appeared to remain stationary, and the end-effector did not move toward the target position. The behaviour was completely reproducible across all viewpoints and noise conditions.

\textbf{Root cause.} The IK joint increments were being written to \texttt{qpos[0:7]} instead of \texttt{qpos[7:14]}. This meant that instead of updating the arm joint angles, the controller was modifying the free joint of the target object. The first three elements of \texttt{qpos[0:7]} are the object's $(x, y, z)$ translation, and the next four are its orientation quaternion. The IK increments, which are joint-angle values in radians (typically in the range $[-0.5, 0.5]$), were being interpreted as metre displacements and quaternion components, causing the object to teleport to arbitrary positions.

\textbf{Resolution.} Correcting the index from \texttt{qpos[0:7]} to \texttt{qpos[7:14]} immediately resolved the problem. The arm began moving correctly, and the object remained stationary on the table until contact.

\textbf{Lesson.} MuJoCo's flat \texttt{qpos} array concatenates all joint positions in the order they appear in the body hierarchy. When the scene contains free joints (which contribute 7 elements each), the arm joint indices are offset accordingly. The offset must be determined by careful inspection of the scene XML and the joint ordering.

\subsection{Bug 2: Camera Orientation (Looking Away from Scene)}
\label{sec:bug_camera}

\textbf{Symptoms.} After positioning the camera at the correct spherical coordinates, the rendered depth image showed only the far plane (all pixels at maximum depth). No objects were visible in the image, despite the camera being positioned at a location that should have a clear view of the table and cylinder.

\textbf{Root cause.} The initial camera orientation code used a look-at rotation matrix where the camera's $+Z$ axis pointed toward the target. However, MuJoCo cameras look along $-Z$, not $+Z$. This meant the camera was facing \emph{away} from the scene, pointing into empty space behind its position.

\textbf{Resolution.} The rotation matrix was corrected to use columns $(\hat{\mathbf{r}}, \hat{\mathbf{u}}, -\hat{\mathbf{f}})$ where $\hat{\mathbf{f}}$ is the forward direction toward the target. This places the $-Z$ axis in the forward direction, consistent with MuJoCo's camera convention.

\subsection{Bug 3: Depth Buffer Saturation}
\label{sec:bug_depth}

\textbf{Symptoms.} After fixing the camera orientation, the depth buffer contained values but they were all at or near the far clipping plane value. The rendered depth image appeared uniform, with no discernible structure. Point clouds generated from this depth buffer were either empty or contained only points far from the expected scene geometry.

\textbf{Root cause.} This was a secondary consequence of Bug~2. While the camera orientation had been partially corrected, a sign error in the quaternion conversion resulted in the camera pointing approximately 90° away from the intended direction. The depth buffer was technically valid---it contained the distances to whatever geometry the camera happened to see---but the field of view did not include the target object or table.

\textbf{Resolution.} A complete rewrite of the quaternion conversion code, with explicit unit tests comparing the resulting camera direction against the expected look-at vector, resolved the issue. The quaternion conversion from rotation matrix was implemented using the Shepperd method, which handles all cases (including the degenerate case where the trace of the rotation matrix is negative) robustly.

\subsection{Bug 4: Gripper Contact Problem}
\label{sec:bug_gripper}

\textbf{Symptoms.} When the arm successfully moved to the correct position above the cylinder and the gripper closed, the fingers would close through the object without gripping it. Alternatively, the fingers would stop closing at a gap width larger than the cylinder diameter, failing to make contact.

\textbf{Root cause.} The finger geometry, constructed from primitive box shapes, had dimensions that did not properly match the cylinder radius. The finger inner faces were positioned at $\pm 0.040$\,m from the gripper centre (matching the finger joint range of $[0, 0.04]$\,m), but the cylinder radius was 0.036\,m. When the fingers closed to their minimum separation, the inner surfaces were approximately 0.070\,m apart---wider than the cylinder diameter of 0.072\,m, preventing contact. Additionally, MuJoCo's contact detection requires a minimum overlap (the ``margin'' parameter) of approximately 1\,mm between geom surfaces for a contact to be registered.

\textbf{Resolution.} The finger geometry was adjusted to ensure that the inner faces are positioned at $\pm 0.035$\,m from centre (using box size 0.008\,m with offset 0.005\,m from the joint axis), providing approximately 1\,mm of overlap with the cylinder surface when the fingers are fully closed. The cylinder radius was confirmed at 0.036\,m, and the contact parameters (\texttt{condim=4}, high friction) were tuned to maximise the normal force at contact.

Even with these adjustments, reliable lifting was not achieved across all conditions. The primitive-shape finger geometry lacks the detailed contact surfaces (fingertip pads, serrations) of the real Panda gripper, which are critical for generating the friction forces needed to support the object against gravity. This limitation motivated the adoption of the proximity-based success criterion described in Section~\ref{sec:success_criterion_detail}.

\section{From Physical Lift to Proximity Criterion}
\label{sec:lift_to_proximity}

The initial experimental design intended to evaluate grasp success by a physical lift criterion: after the gripper closes, the arm lifts the object vertically, and the trial is successful if the object reaches a height of 0.55\,m (approximately 10\,cm above its resting position). This is the gold standard for grasp evaluation in simulation~\cite{fang2020graspnet}.

In the visual demonstration script (\texttt{demo\_grasp.py}), which runs with the MuJoCo viewer open, individual grasps could sometimes succeed with this criterion: the viewer allowed real-time observation of the contact dynamics, and the grasp parameters (approach speed, gripper closure rate) could be manually tuned for each trial.

However, achieving consistent lift success across 432 headless (no viewer) trials proved impractical, and the underlying reasons all trace back to the same root cause: the primitive-shape gripper cannot reproduce the fine contact mechanics of the real hardware. The fingers have flat box surfaces rather than the real Panda gripper's contoured fingertips, so the contact area is extremely small and the resulting friction force is sensitive to sub-millimetre variations in finger closure. This sensitivity is compounded by the target object itself: the light cylinder (0.05\,kg) is easily displaced by any asymmetric contact force, so if one finger reaches the surface slightly before the other, the object is pushed sideways before the grasp can stabilise, and the tendon actuator---which applies equal force to both fingers regardless of this asymmetry---cannot correct for it. In the visual demonstration script these problems could be caught and corrected by hand, nudging the approach trajectory in real time; the batch experiment, running headless with no per-trial tuning, had no such recourse.

The proximity criterion was adopted as a principled alternative that maintains the causal validity of the experimental design. The key insight is that the thesis's causal claim concerns the relationship between perception quality and grasp \emph{proposal} accuracy, not the robot's ability to physically execute a perfect grasp. The proximity criterion measures precisely the quantity that the SCM models: whether the perception-derived grasp position is close enough to the object centroid that, with a properly functioning gripper, contact \emph{would} be established.

\section{Automated Control Pipeline Summary}
\label{sec:pipeline_summary}

To clarify the complete chain of causation from perception to motion, this section summarises what exactly moves the arm in the simulation:

\begin{enumerate}
  \item The \textbf{Jacobian DLS} method computes a joint velocity increment $\Delta\mathbf{q} \in \mathbb{R}^7$ from the position error.

  \item The increment is \textbf{scaled and added to} $\texttt{data.qpos[7:14]}$, updating the 7 arm joint angles in MuJoCo's internal state vector.

  \item The updated joint angles are \textbf{mirrored into} $\texttt{data.ctrl[0:7]}$, commanding MuJoCo's position actuators to drive toward the new configuration.

  \item MuJoCo's \textbf{PD actuators generate torques}: the gain term produces a restoring torque proportional to the error between $\texttt{ctrl}$ and the current joint angle, and the bias term provides gravity compensation and damping.

  \item \texttt{mj\_step} \textbf{integrates the equations of motion}, advancing the simulation by one timestep. The joint torques accelerate the links, the positions update, and the arm physically moves.

  \item This process \textbf{repeats} at 500\,Hz (timestep = 0.002\,s) until convergence or timeout.
\end{enumerate}

No human operator intervenes at any stage. The entire process is driven by the Python control script calling MuJoCo functions in a loop.

\section{Perception Pipeline Detail}
\label{sec:perception_pipeline}

The perception pipeline transforms the MuJoCo scene into the input format expected by Contact-GraspNet. The steps are:

\begin{enumerate}
  \item \textbf{Render depth.} MuJoCo's \texttt{Renderer} produces a $480 \times 640$ depth buffer as a NumPy array of float32 values representing distances in metres.

  \item \textbf{Add noise.} Gaussian noise $\mathcal{N}(0, \sigma_d^2)$ is added per-pixel. Values are clipped to $\geq 0$.

  \item \textbf{Render segmentation.} A second render pass produces the segmentation buffer, a $480 \times 640 \times 2$ array where channel 0 contains the geom ID at each pixel. The code iterates over all geoms in the model, identifies those belonging to the target body, and creates a binary mask.

  \item \textbf{Build camera intrinsics.} The $3 \times 3$ intrinsic matrix $\mathbf{K}$ is constructed from the MuJoCo camera's field-of-view parameter (Equation~\ref{eq:focal_length}).

  \item \textbf{Save to NPZ.} The depth, intrinsics, and segmentation are saved to a temporary \texttt{.npz} file, which is loaded by CGN's data loader.

  \item \textbf{CGN point cloud extraction.} CGN's built-in \texttt{extract\_point\_clouds} function back-projects the depth map using the intrinsics matrix and filters points by a z-range $[0.1, 2.0]$\,m.

  \item \textbf{Downsample.} If $\rho < 1.0$, random indices are selected without replacement to keep $\rho \times N$ points from the full point cloud and corresponding segments.

  \item \textbf{CGN inference.} The (possibly downsampled) point cloud is passed to CGN's \texttt{predict\_scene\_grasps}, which returns grasp poses, scores, and contact points.
\end{enumerate}

The following code snippet shows the core perception function:

\begin{lstlisting}[caption={Depth rendering with noise injection and segmentation.},label={lst:render}]
def render_depth_seg(model, data, sigma_d=0.0, rng=None):
    renderer = mujoco.Renderer(model,
                   height=IMG_H, width=IMG_W)
    renderer.enable_depth_rendering()
    renderer.update_scene(data, camera=CAM_NAME)
    depth_raw = renderer.render().copy()
    renderer.disable_depth_rendering()

    renderer.enable_segmentation_rendering()
    renderer.update_scene(data, camera=CAM_NAME)
    seg = renderer.render()
    renderer.close()

    # Binary segmentation: target object = 1
    tgt_bid = mujoco.mj_name2id(model,
        mujoco.mjtObj.mjOBJ_BODY, TARGET_BODY)
    gid_img = seg[:, :, 0]
    seg_map = np.zeros(gid_img.shape, dtype=np.int32)
    for gid in range(model.ngeom):
        if model.geom_bodyid[gid] == tgt_bid:
            seg_map[gid_img == gid] = 1

    # Noise injection (causal variable sigma_d)
    if sigma_d > 0.:
        depth_noisy = np.clip(
            depth_raw + rng.normal(0., sigma_d,
                                   depth_raw.shape),
            0., None).astype(np.float32)
    else:
        depth_noisy = depth_raw.copy()

    return depth_noisy, build_K(model), seg_map
\end{lstlisting}

\subsection{Rationale for Variable Levels}

The specific levels for each variable were chosen based on the following considerations:

\textbf{Depth noise ($\sigma_d$):} The four levels span the range from perfect sensing ($\sigma_d = 0$) to severe degradation ($\sigma_d = 0.04$\,m). The intermediate value $\sigma_d = 0.005$\,m is representative of high-quality commercial depth sensors at typical operating distances of 0.5--1.5\,m~\cite{khoshelham2011accuracy}. The value $\sigma_d = 0.02$\,m represents moderate degradation, and $\sigma_d = 0.04$\,m represents conditions under which the depth signal is heavily corrupted---at this level, the noise standard deviation is comparable to the cylinder's radius (0.036\,m), meaning the object geometry is essentially lost in the noise.

\textbf{Point cloud sparsity ($\rho$):} The four levels provide a uniform progression from full density ($\rho = 1.0$) to 75\% reduction ($\rho = 0.25$). Random subsampling is used rather than structured removal because it provides the most causally clean operationalisation: each point is independently retained or removed with probability $\rho$, ensuring that the sparsity variable is statistically independent of all other variables.

\textbf{Camera elevation ($\phi$):} Three levels span the range from a relatively low viewpoint ($30°$) to a steep overhead view ($60°$). Lower elevations provide more of the object's side profile but see less of the top surface; higher elevations see the top surface clearly but compress the lateral dimensions. The $45°$ level represents a typical camera mounting angle in industrial bin-picking applications.

\textbf{Camera azimuth ($\theta$):} Three levels cover a quarter of the viewing circle. The full $360°$ range was not necessary because the cylinder is rotationally symmetric; different azimuth angles produce different camera positions relative to the arm (which can cause occlusion) but the object itself appears identical from all azimuths.

\subsection{Random Seeds}

Each condition is repeated with three random seeds ($\text{seed} = k \times 10000 + i$ where $k \in \{0, 1, 2\}$ and $i$ is the trial index). The random seed controls: (a) the realisation of the Gaussian depth noise, (b) the random subset of points retained during downsampling, and (c) any stochastic behaviour within Contact-GraspNet's inference pipeline. Using three seeds per condition provides a measure of the variability inherent in the pipeline and allows the SCM to be fitted on data that captures this natural stochasticity.

\subsection{Sample Size Justification and Dataset Adequacy}
\label{sec:sample_size}

The 432 trials are a principled consequence of the full-factorial design rather than an arbitrary choice. This subsection addresses four questions that bear on the adequacy of the dataset: why full-factorial, why three seeds, why these specific grid levels, and why additional causal variables were not included.

\paragraph{Why full-factorial?}
The full-factorial design crosses every level of every variable, so the joint distribution of $(\sigma_d, \rho, \phi, \theta)$ is perfectly balanced. Balance is not merely aesthetic: it is a prerequisite for unconfounded causal estimation. In a balanced design, the marginal effect of $\sigma_d$ is estimated by averaging over all combinations of the remaining three variables; no subset of $\phi$ or $\theta$ values is over-represented in any $\sigma_d$ cell. Had a fractional-factorial or convenience-sample design been used, some first-order or interaction effects would be aliased, meaning that the SCM structural equations would conflate effects that should be disentangled. Full-factorial designs are the standard for mechanistic causal studies precisely because they guarantee this orthogonality~\cite{montgomery2017design}.

\paragraph{Why three seeds per condition?}
Three replications per condition is the minimum that permits a within-cell variance estimate with two degrees of freedom---sufficient for the ordinary least squares regression that fits each SCM structural equation. With one replication per condition there is no variance estimate at all; with two there is one degree of freedom, which makes residual diagnostics unreliable. Three seeds, giving $144 \times 3 = 432$ trials in total, is therefore the smallest design consistent with the OLS fitting procedure.

\paragraph{Are three seeds sufficient given the observed signal strength?}
The relevant question for an SCM study is not whether the design has high statistical power in the classical sense, but whether the causal effects are estimated with sufficient precision to support the counterfactual queries posed. The dominant effect---depth noise---produces a success-rate range of 70.4 percentage points ($\sigma_d = 0$: 70.4\%; $\sigma_d = 0.04$: 0.0\%) across 108 trials per level. A one-sided binomial test for the 0.0\% vs.\ 70.4\% comparison has power $> 0.999$ at $\alpha = 0.05$, even with the minimum replication scheme. The no-grasps rate at $\sigma_d = 0.04$ (87\% of 108 trials) is similarly unambiguous. Even the weakest observed effect---the non-monotone $\rho$ response---is interpretable: the deviation of $\rho = 1.0$ from the trend (25.9\% success vs.\ 37.0\% at $\rho = 0.75$) is consistent across all four $\sigma_d$ levels and has a mechanistic explanation (dense point clouds at moderate noise levels include more corrupted outliers than moderately downsampled ones). In short, the signal-to-noise ratio throughout the dataset is sufficiently high that additional replication would narrow confidence intervals without changing any qualitative conclusion.

\paragraph{Why not finer grid resolution?}
Adding intermediate $\sigma_d$ levels (e.g.\ $\sigma_d = 0.01$ or $0.03$\,m) would smooth the interpolation between existing breakpoints but would not alter the causal argument. The SCM's structural equations are regression models that can be queried at arbitrary out-of-sample values of the exogenous variables; counterfactual inference at $\sigma_d = 0.01$ does not require $\sigma_d = 0.01$ to appear explicitly in the training data. Similarly for $\rho$: additional levels would refine the $\sigma_d \times \rho$ interaction surface (Table~\ref{tab:interaction}) but would not change the finding that $\sigma_d$ dominates at all severity levels. Each additional level of any four-level variable would increase the trial count by 25\% (36 new conditions $\times$ 3 seeds), adding approximately one hour of compute time with marginal scientific return.

\paragraph{Why not additional causal variables?}
Variables such as object geometry, surface reflectance, ambient lighting, and target-object mass are legitimate confounders in real robotic deployments. They are excluded because the thesis's contribution is methodological: to demonstrate that counterfactual SCM inference can identify which perceptual variable caused a given failure. This demonstration requires a dataset in which the ground-truth cause is known to the experimenter---that is, it was deliberately manipulated. Each additional variable multiplies the grid by the number of its levels (a second four-level variable would double the trial count to 864, a third to 1728, and so on) and would shift the focus from methodological validation to empirical survey. The scope is deliberately bounded so that the SCM fitting, counterfactual procedure, and LLM baseline comparison can all be completed within the project timeline.

\paragraph{Data quality.}
Six of the 432 trials (1.4\%) terminated with a Windows file-locking error (\texttt{WinError~32}) caused by simultaneous access to the temporary NPZ file by the main process and the Contact-GraspNet data loader. These six trials have \texttt{NaN} in their \texttt{success} column. They are distributed across different regions of the grid ($\sigma_d \in \{0,\,0.005,\,0.04\}$; $\phi \in \{30°,\,45°,\,60°\}$) with no detectable relationship between the error and the causal variables, confirming that the missingness is not informative. The effective analysis sample used in all quantitative results is therefore 426 complete trials (see Section~\ref{sec:data_collection}).

\section{Evaluation Metrics}
\label{sec:metrics}

The following metrics are used to evaluate the experimental results:

\begin{itemize}
  \item \textbf{Attribution accuracy:} The fraction of single-cause failure cases where the counterfactual diagnosis $v^*$ matches the variable that the experimenter deliberately set to its extreme (degraded) value. For example, if a trial had $\sigma_d = 0.04$ and all other variables at nominal values, and the SCM attributes the failure to $\sigma_d$, this counts as a correct attribution.

  \item \textbf{Consistency:} For the LLM baseline, the standard deviation of the attributed cause across three repeated queries per failure case. For the SCM, attribution is deterministic by construction (given the same inputs, the same diagnosis is always produced).

  \item \textbf{Explanation quality:} A human-scored rubric assessing whether the LLM's natural-language justification correctly identifies the causal mechanism through which the attributed variable caused the failure.

  \item \textbf{SCM validation metrics:} For each structural equation, the coefficient of determination $R^2$ and root mean square error (RMSE) on held-out trials. For the logistic outcome model, the area under the ROC curve (AUC).
\end{itemize}

\section{Data Collection}
\label{sec:data_collection}

Data was collected using the \texttt{run\_experiments.py} script, which iterates over all 432 trial conditions sequentially. Each trial takes approximately 15--30 seconds on a consumer-grade CPU (the Contact-GraspNet inference is the dominant cost, running on CPU mode). The total data collection time was approximately 3--4 hours.

Results are logged to a CSV file (\texttt{results/experiment\_results.csv}) with the following columns: \texttt{trial\_id}, \texttt{sigma\_d}, \texttt{rho}, \texttt{phi}, \texttt{theta}, \texttt{seed}, \texttt{C\_pc}, \texttt{q\_grasp}, \texttt{e\_pose}, \texttt{n\_grasps}, \texttt{success}, \texttt{obj\_z\_final}, \texttt{error}.

The \texttt{error} column records any exceptions that occurred during the trial. Two distinct error types appear in the dataset: \texttt{no\_grasps}, which records the causal outcome that CGN produced zero grasp candidates (and is therefore itself a meaningful observation, not missing data), and file-access errors that prevented the trial from producing any outcome. The latter category affects six trials (1.4\% of the dataset) and is discussed in Section~\ref{sec:sample_size}; all six are excluded from analyses that depend on the \texttt{success} column, giving an effective analysis sample of 426 complete trials.

The \texttt{--resume} flag allows the script to skip trials that have already been completed, enabling recovery from interrupted runs. This proved essential during development, as the full 432-trial run was interrupted several times by file-locking errors (\texttt{WinError~32}) caused by the temporary NPZ file being accessed concurrently by the main process and the CGN data loader.

\section{The Three-Stage Decomposition}
\label{sec:decomposition}

Every trial passes through three stages in a fixed order: Contact-GraspNet either does or does not return candidates; the selected pose either does or does not clear the open-hand collision check, which we refer to as the \emph{gate}; and the executed grasp either does or does not hold the object through the lift. Marginal success therefore factorises exactly as
\begin{equation}
  P(Y = 1) \;=\; \underbrace{P(N > 0)}_{\text{proposal}} \cdot \underbrace{P(G = 1 \mid N > 0)}_{\text{gate}} \cdot \underbrace{P(Y = 1 \mid G = 1)}_{\text{execution}},
  \label{eq:decomposition}
\end{equation}
where $N$ is the number of candidates and $G$ indicates that the selected pose is collision-free.

Aggregated over the whole design the three factors are 94.6\% (7{,}149/7{,}560), 23.1\% (1{,}648/7{,}149), and 23.1\% (380/1{,}648; Wilson 95\% CI 21.1--25.2\%), whose product recovers the 5.0\% marginal rate. Reporting these factors separately is what makes the rest of this chapter possible: a variable can act by making poses geometrically invalid, by making valid poses physically bad, or by both at once in opposite directions, and the marginal rate cannot distinguish these cases.

The execution factor also confirms that the outcome variable is not degenerate. Among trials that clear the gate, roughly three quarters still fail, so grasp success is not merely a relabelling of the collision check and the mediating variables have genuine residual variance to explain.

Over the same range, success given that a pose cleared the gate collapses from 65.6\% to 0.2\%, with the sharpest transition between $\sigma_d = 0.01$ (53.5\%) and $\sigma_d = 0.015$ (5.2\%).

\section{Object Geometry Dominates the Execution Channel}

\section{Two Associational Reversals}
\label{sec:reversals}

The dataset contains two places where the marginal association points in the opposite direction to the within-stratum relationship. Both are dissolved by conditioning on the structure, and together they form the empirical case for the mechanistic audit.

The first is the non-monotone noise effect of Section~\ref{sec:noise_channels}. Marginally, moving from a noise-free sensor to $\sigma_d = 0.005$ doubles the success rate. Conditional on clearing the gate, the same move is neutral-to-mildly-positive, and beyond it the effect is catastrophic; the apparent benefit comes almost entirely from the gate-pass rate rising from 8.8\% to 14.1\%.

The second concerns the pose-error mediator. Among gate-passing trials the raw correlation between $e_{\text{pose}}$ and success is \emph{positive} for two of three objects ($+0.09$ for the box, $+0.25$ for the cylinder, $-0.15$ for the mustard bottle), which would suggest that worse localisation helps. Within every noise stratum the relationship has the expected sign: at $\sigma_d = 0$ successful trials average $e_{\text{pose}} = 0.083$\,m against 0.119\,m for failures, at $\sigma_d = 0.0025$ it is 0.075\,m against 0.110\,m, and at $\sigma_d = 0.005$ it is 0.073\,m against 0.094\,m. The reversal arises because $\sigma_d$ lowers $e_{\text{pose}}$ and destroys success simultaneously, so pooling across noise levels inverts the sign.

Neither reversal is exotic; both are ordinary confounding. The point is that both are present in the observable outcome data that a diagnostic system would receive, and both would lead an associational diagnostician to a conclusion of the wrong sign. A pre-registered structural model that knows the pipeline's stage order avoids both without having to discover them.

\section{Top-$k$ Collision Filtering as an Intervention on the Gate}
\label{sec:topk}

Section~\ref{sec:decomposition} shows that the gate is where most trials are lost. Contact-GraspNet practice normally addresses this by considering more than the top-ranked proposal, so we ran a targeted intervention: at a single favourable viewpoint ($\phi = 55°$, $\theta = 45°$, $\sigma_d = 0$, $\rho = 1.0$) with the cylinder, candidates were rejected in rank order until a collision-free pose was found, up to $k = 20$. Across 100 trials this protocol reaches 89\% success, and every one of the 11 failures is a trial in which no collision-free pose was found within the top 20.

Two comparisons put this in context. The matched cell in the main study, which executes the top-ranked pose only, succeeded in 2 of 5 trials; pooled over all viewpoints at $\sigma_d = 0$ and $\rho = 1.0$, the cylinder's success rate under top-1 selection is 10.0\% with a gate-pass rate of 11.1\%. The intervention therefore removes most of the gate loss and confirms that the low headline rate of Section~\ref{sec:descriptive} is dominated by pose selection rather than by perception or execution.

Three caveats apply. The favourable viewpoint was chosen after inspecting the main grid, so the 89\% figure characterises the protocol's ceiling rather than an expected operating rate. The filtered protocol uses the lighter clamp-and-lift criterion rather than the full shake disturbance used in the main study, so part of the gap is criterion rather than selection. And within this cell success coincides exactly with clearing the gate, which means the filtered configuration carries no execution-channel information; it is a boundary case in which the outcome is determined entirely by pose availability, and it is therefore not a suitable basis for fitting the SCM.

\textbf{Equation 1 ($C_{pc}$).} Point cloud completeness is explained almost entirely by viewpoint geometry ($R^2 = 0.893$). The estimated slope is $\hat{\alpha}_{\phi} = -0.000259$\,unit/degree (95\% CI: $[-0.000271, -0.000247]$, $p < 0.001$), confirming a strong monotone decrease in coverage as the camera moves to more overhead angles. The $\theta$ coefficient is small but significant ($\hat{\alpha}_{\theta} = +8.6 \times 10^{-5}$, $p < 0.001$), reflecting a slight rotational asymmetry in the scene due to the Panda arm body. Crucially, $\sigma_d$ and $\rho$ are excluded from this equation by construction: the segmentation mask from which $C_{pc}$ is computed is rendered \emph{before} noise injection and downsampling, so these variables have zero causal effect on $C_{pc}$, as confirmed empirically (range of $C_{pc}$ across $\sigma_d$ levels: $[0.00969, 0.00988]$; across $\rho$ levels: $[0.00965, 0.00988]$).

\textbf{Equation 2A (has\_grasps).} The hurdle equation achieves AUC~=~0.943 with pseudo-$R^2 = 0.554$. Depth noise is the dominant predictor: $\hat{\beta}_{\sigma_d} = -169.3$ on the log-odds scale (OR $\approx 0$, $p < 0.001$), meaning that any non-trivial noise level dramatically reduces the probability that CGN produces a grasp proposal. Camera elevation $\phi$ is also significant (OR~=~0.886 per degree, $p < 0.001$): each additional degree of elevation reduces the odds of a grasp proposal by approximately 11\%. Point cloud sparsity $\rho$ is \emph{not} significant in this equation ($p = 0.144$, OR~=~2.37), indicating that whether CGN produces \emph{any} proposal is driven by noise, not sparsity.

\textbf{Equation 2B ($n_{\text{grasps}}$).} When conditioned on has\_grasps~=~1, sparsity $\rho$ becomes highly significant (exp(coef)~=~3.56, $p < 0.001$): denser point clouds produce more grasp candidates. This cleanly separates the roles of $\sigma_d$ and $\rho$: \emph{depth noise determines whether any proposal is generated; sparsity determines how many are generated}. This distinction is critical for interpreting the mediation results in Equation~4.

\textbf{Equation 3 ($q_{\text{grasp}}$).} Grasp confidence is well-explained by the conditioning variables ($R^2 = 0.699$). The $\log(n_{\text{grasps}})$ term is strongly positive (coef~=~0.025, $p < 0.001$), confirming that the order-statistic correction is necessary: with more candidates, the maximum-score proposal is systematically better. Sparsity $\rho$ carries a negative and significant coefficient (coef~=~$-0.041$, $p < 0.001$), a counterintuitive result attributable to the combination of order-statistic selection and the fact that sparser clouds at moderate noise levels may concentrate proposals near correctly-observed surface patches. Depth noise $\sigma_d$ is not significant among surviving trials ($p = 0.255$), consistent with selection: the severe-noise trials that would show the strongest $\sigma_d$ effect are already censored in the has\_grasps~=~0 category.

\textbf{Equation 4 ($e_{\text{pose}}$).} A mediation analysis reveals qualitatively different causal pathways for $\sigma_d$ and $\rho$: depth noise has 10.9\% of its effect on pose error mediated through grasp quality, with the remaining 89.1\% acting directly; sparsity has 90.9\% of its effect mediated through grasp quality. This means $\sigma_d$ corrupts the point cloud geometry directly, causing large pose displacements regardless of which grasp is selected, while $\rho$ primarily influences $e_{\text{pose}}$ indirectly through its effect on candidate quality. The direct effect of $q_{\text{grasp}}$ on $e_{\text{pose}}$ is negative and significant (coef~=~$-0.161$, $p = 0.002$): higher confidence scores correspond to smaller pose errors, validating the mechanistic assumption that CGN's confidence is a meaningful proxy for proposal quality.

\section{Effect of Individual Variables on Grasp Success}
\label{sec:dose_response}

The dose--response relationships are summarised in Table~\ref{tab:success_by_var}. The key observations are:

\textbf{Depth noise ($\sigma_d$)} is the strongest single predictor of failure. The success rate drops from 70.4\% at $\sigma_d = 0$ to 42.6\% at $\sigma_d = 0.005$, 11.1\% at $\sigma_d = 0.02$, and 0.0\% at $\sigma_d = 0.04$. This monotone decrease is consistent with the causal hypothesis that noise degrades point cloud geometry, reduces CGN confidence ($\bar{q}$ drops from 0.242 to 0.163), and increases pose error ($\bar{e}_{\text{pose}}$ increases from 0.050\,m to 0.175\,m). At $\sigma_d = 0.04$ all failures are either \textit{no grasps} (98 trials) or pose-error failures (10 trials), confirming that this noise level destroys the point cloud geometry below CGN's minimum viable input quality.

\textbf{Point cloud sparsity ($\rho$)} shows a non-monotone effect. Success rates are 25.9\% ($\rho = 1.0$), 37.0\% ($\rho = 0.75$), 32.4\% ($\rho = 0.50$), and 28.7\% ($\rho = 0.25$). The non-monotonicity arises because the relationship interacts strongly with $\sigma_d$: at $\sigma_d = 0$, sparsity has a relatively small negative effect; at moderate noise levels ($\sigma_d = 0.005$), $\rho = 0.75$ yields higher success than $\rho = 1.0$, suggesting that moderate downsampling removes noise-corrupted outlier points. This interaction is explored further in Section~\ref{sec:interaction}.

\textbf{Camera elevation ($\phi$)} affects success primarily through the \textit{no grasps} pathway. At $\phi = 60°$, 71 of 144 trials (49.3\%) produced no grasps from CGN, compared to 38/144 (26.4\%) at $\phi = 45°$ and 32/144 (22.2\%) at $\phi = 30°$. The steep downward view at $60°$ causes the robot arm to occlude the camera at $\theta = 0°$ (all 36 such trials at $\phi = 60°$, $\theta = 0°$ produced zero grasps with $C_{pc} \approx 5 \times 10^{-5}$). Among trials that did produce grasps, $\phi = 45°$ yields the highest success rate. The systematic 6\,cm lateral bias of CGN at $\phi = 30°$ is the primary driver of failures at that elevation.

\textbf{Camera azimuth ($\theta$)} shows a steady decline: 42.4\% at $\theta = 0°$, 34.0\% at $\theta = 45°$, and 16.7\% at $\theta = 90°$. At $\theta = 90°$, the camera views the scene laterally, which reduces the number of visible object pixels ($C_{pc}$) and the number of grasp candidates. The effect is amplified at $\phi = 60°$ where arm occlusion at $\theta = 0°$ dominates, flattening what would otherwise be a monotone relationship.

\section{Observations from the Experimental Data}
\label{sec:observations}

Several patterns are directly observable in the raw experimental data collected in \texttt{experiment\_results.csv}:

\begin{itemize}
  \item \textbf{Maximum noise produces a qualitatively distinct failure mode.} At $\sigma_d = 0.04$\,m, CGN produced zero grasps in 94 of 108 trials (87.0\%). The remaining 10 trials that did produce grasps all failed the proximity criterion. The 0.0\% success rate at $\sigma_d = 0.04$ is therefore driven by two compounding mechanisms: point cloud destruction (no-grasps) and extreme pose error in the rare cases where a grasp is generated. This is qualitatively different from the moderate-noise regime ($\sigma_d = 0.02$, 11.1\% success), where failures arise from inaccurate but non-zero pose estimates.

  \item \textbf{Arm occlusion at $\phi = 60°$, $\theta = 0°$ is a systematic dead zone.} At this viewpoint, all 36 trials (including all three noise levels) produced zero grasps, with $C_{pc} \approx 5 \times 10^{-5}$ (effectively zero object pixels visible). The Panda arm body completely occludes the camera's line of sight to the target at this angle. These 36 trials are a structural artefact of the scene geometry rather than a perceptual degradation effect and should be noted when interpreting the $\phi = 60°$ and $\theta = 0°$ marginals.

  \item \textbf{Under clean conditions, lower elevation outperforms higher elevation.} At $\sigma_d = 0$, the success rates are: $\phi = 30°$: 89\% (32/36), $\phi = 45°$: 83\% (30/36), $\phi = 60°$: 39\% (14/36). Contrary to the expectation that a steeper viewpoint provides better top-surface coverage, the lower elevation $\phi = 30°$ achieves the highest clean success rate. The $\phi = 30°$ CGN lateral bias ($\approx$6\,cm) is within the $D_\tau = 0.065$\,m threshold and therefore does not prevent success under clean conditions. The degradation at $\phi = 60°$ is dominated by the arm-occlusion dead zone.

  \item \textbf{Point cloud sparsity has a counter-intuitive relationship with success.} Under clean conditions ($\sigma_d = 0$), the success rates by $\rho$ are: $\rho = 0.75$: 85\% (23/27), $\rho = 0.50$: 74\% (20/27), $\rho = 0.25$: 70\% (19/27), $\rho = 1.0$: 52\% (14/27). The full-density point cloud ($\rho = 1.0$) performs worst. This is likely a confound from the subset composition: the 27 clean, $\rho = 1.0$ trials include a proportionally higher representation of the $\phi = 60°$ arm-occlusion conditions. Nonetheless, the data confirm that CGN is robust to moderate downsampling: even $\rho = 0.25$ achieves 70\% success under perfect sensing.
\end{itemize}

\section{Assumptions and Limitations}
\label{sec:limitations}

\begin{enumerate}
  \item \textbf{Expert-specified causal graph.} The causal DAG (Figure~\ref{fig:causal_dag}) is specified based on domain knowledge rather than discovered from data. If the true causal structure differs---for example, if there are direct effects between exogenous variables that are not modelled---then the counterfactual results may be incorrect. Causal discovery algorithms could be applied to the collected data to test the assumed structure, but this is left for future work. This limitation is partly a mathematical necessity rather than a study weakness: Yang and Bareinboim~\cite{yang2025hierarchy} prove, via a Hierarchy Theorem for graphical models, that operating at $\mathcal{L}_3$ (counterfactual layer) requires assumptions that are strictly stronger than any $\mathcal{L}_1$ or $\mathcal{L}_2$ dataset can falsify. The appropriate response---grounding the DAG in domain knowledge and validating its $\mathcal{L}_2$ predictions (interventional distributions) against experimental data---is precisely what the factorial design enables.

  \item \textbf{Gaussian noise model.} The additive Gaussian noise model is a first-order approximation of real sensor degradation. Real depth sensors exhibit structured noise patterns including IR depth failure near specular surfaces, systematic bias at depth discontinuities, and multipath interference. These effects are not captured by the Gaussian model.

  \item \textbf{Proximity-based success criterion.} The proximity criterion replaces a full contact-mechanics grasp evaluation. A rigid-body lift outcome would be more physically faithful but required contact stiffness and actuator tuning beyond the scope of the current work. The criterion is nonetheless causally valid: it measures precisely the quantity the SCM models, namely whether the perception-derived grasp position is close enough to the object to enable contact.

  \item \textbf{Primitive-shape robot model.} The robot arm is approximated with primitive shapes (capsules and boxes). The kinematics are identical to the real Panda; only the visual and collision geometry differs. For the perception pipeline, only the depth image of the target object matters; the arm geometry enters only through potential occlusion, which is minimal in the chosen camera configurations.

  \item \textbf{Systematic CGN bias.} Contact-GraspNet exhibits a systematic lateral bias of approximately 6\,cm at $\phi = 30°$ even under clean inputs. This is a property of the network's training distribution, not introduced by the experimental perturbations, and is factored into the calibrated threshold $D_\tau$.

  \item \textbf{Single object.} All experiments use a single cylindrical target object. Results may not generalise to objects with more complex geometries, though the causal framework itself is geometry-agnostic.

  \item \textbf{Simulation only.} All experiments are conducted in simulation. No claim of sim-to-real transfer is made.

  \item \textbf{Diagnosis only.} Recovery actions are outside scope; the thesis addresses only the diagnostic stage of the failure recovery pipeline.

  \item \textbf{Single-cause attribution, and its dependence on intervention magnitude.} Using the precise definitions of Section~\ref{sec:single_cause_def}, the counterfactual ground-truth simulation (292 failed trials, each re-run under four single-variable clean-baseline interventions) found that \textbf{167 of 292 failures (57.2\%) have no single-variable fix}: resetting any one of $\sigma_d$, $\rho$, $\phi$, or $\theta$ individually to its clean baseline is insufficient to convert the failure to a success. Of the remaining 125 fixable cases, $\sigma_d$ alone repairs 36, $\theta$ alone repairs 35, $\phi$ alone repairs 23, and $\rho$ alone repairs 1. The "none" failures are concentrated at $\phi = 60°$ (98 of 167), where overhead camera geometry creates an irreducible multi-causal failure mode. Hypothesis~\ref{hyp:accuracy} is therefore evaluated only on the 125 single-cause trials; the 167 multi-cause failures are reported separately as a characterisation of the joint-cause regime that lies outside the scope of single-variable attribution. This 57.2\% figure is computed from ground-truth re-simulation (i.e.\ actually re-running MuJoCo and CGN under the intervention), not from the fitted SCM, so it is not itself an artefact of surrogate misspecification. However, the SCM's \emph{predicted} counterfactual improvements $\Delta_v$ (Section~\ref{sec:counterfactual_diagnosis}), used for attribution and compared against this ground truth, are computed through the linear-logistic surrogate. Because the surrogate is known to underfit at least one genuine non-linearity (the $\phi = 30°$ CGN bias, Section~\ref{sec:structural_equations}), some disagreement between the SCM's ranked attribution and the ground-truth single/multi-cause label should be expected to reflect surrogate error compounded through abduction, rather than a true absence of a dominant cause. This confound is not separated out in the current attribution-accuracy results and should be treated as a caveat on Hypothesis~\ref{hyp:accuracy}'s interpretation, not on the 57.2\% figure itself.

  A separate and, on reflection, more consequential limitation concerns the \emph{magnitude} of the interventions used to define single-cause versus irreducible. Every counterfactual reset in this thesis resets the chosen variable all the way to its nominal clean-baseline value (e.g.\ $\doop(\sigma_d = 0)$, not $\doop(\sigma_d = 0.02)$). It is therefore possible that some of the 167 "irreducible" failures would in fact be resolved by a smaller, partial correction to a single variable, and would only appear irreducible because the specific magnitude tested here is a full reset rather than the minimal sufficient correction. Equally, it is possible that finer-grained interventions would reveal \emph{more} irreducibility among cases currently counted as single-cause, if the clean-baseline reset happens to overshoot the threshold needed. Neither possibility is ruled out by the present analysis: a systematic sensitivity study, re-running the counterfactual ground-truth procedure at several intermediate magnitudes per variable rather than only at the full clean-baseline reset, was identified during the preparation of this thesis as the appropriate check and is prioritised as future work (Section~\ref{sec:future_work}) rather than attempted under the time constraints of this submission. Until that check is run, the 57.2\% figure should be read as irreducibility \emph{within the specific intervention magnitude tested here}, not as a magnitude-independent property of the failure mode, and Contribution 4 (Section~\ref{sec:contributions}) is stated with that qualification.

  \item \textbf{Minimum within-condition replication.} Each of the 144 conditions was replicated with exactly three random seeds---the minimum sufficient for a two-degrees-of-freedom residual in the OLS structural equations. Confidence intervals on per-condition success rates are correspondingly wide for effects of moderate magnitude (particularly the non-monotone $\rho$ response). The main effects of $\sigma_d$ are insensitive to this limitation given their large magnitude; the $\rho$ interaction and viewpoint effects carry greater uncertainty.

  \item \textbf{Incomplete trials.} Six trials (1.4\%) terminated with a file-locking error and have no recorded outcome. These trials are excluded from outcome-dependent analyses (effective $n = 426$). Their omission is unlikely to introduce systematic bias, as the errors arose from a race condition in the file I/O layer with no relationship to the causal variables.

  \item \textbf{Attribution logic vs.\ actual causation.} Algorithm~\ref{alg:diagnosis} attributes failure to $v^* = \arg\max_v \Delta_v$, selecting the variable with the largest counterfactual improvement. This is a sufficient but not minimal notion of causation. The Halpern--Pearl definition of \emph{actual causation}~\cite{halpern2005causes} imposes additional minimality and normality conditions---for instance, a cause should not remain a cause when a ``smaller'' sufficient cause is identified. Verifying these conditions in the current SCM is left for future work.
\end{enumerate}

\section{Future Work}
\label{sec:future_work}

Several directions for extending this work are identified. The first three are elevated above the rest of the list because they were identified, during the preparation of this thesis, as the extensions that would most directly strengthen or stress-test its central claims, and were left undone only because of the time constraints of the submission rather than any judgement that they are unimportant.

\begin{itemize}
  \item \textbf{Intervention-magnitude sensitivity for irreducibility (highest priority).} As discussed in Section~\ref{sec:limitations}, the 57.2\% irreducible-failure rate is defined relative to a full reset of each variable to its clean-baseline value. Re-running the counterfactual ground-truth procedure of Section~\ref{sec:counterfactual_diagnosis} at a range of intermediate intervention magnitudes per variable (e.g.\ $\sigma_d \in \{0, 0.01, 0.02\}$ rather than only $\sigma_d = 0$) would establish whether irreducibility is a robust property of these failures or an artefact of the specific magnitude chosen. If the rate holds under finer interventions, Contribution 4 is strengthened substantially; if it does not, the honest restatement---irreducibility \emph{within the tested operational range}---is still a meaningful engineering finding. Either outcome is informative, which is what makes this the highest-value remaining experiment.

  \item \textbf{Partial-observability abduction.} Section~\ref{sec:counterfactual_diagnosis} notes that abduction is presently degenerate: the exogenous variables $(\sigma_d, \rho, \phi, \theta)$ are logged directly by the experimenter, so there is nothing about them for the abduction step to infer. A partial-observability variant, in which the true exogenous settings are hidden from the diagnostic system and must instead be inferred from the intermediate variables ($C_{pc}, q_{\text{grasp}}, n_{\text{grasps}}, e_{\text{pose}}$) before the action and prediction steps proceed, would make abduction empirically substantive rather than a bookkeeping formality, and is judged the single highest-value \emph{methodological} addition to the present framework.

  \item \textbf{VLM baseline with image inputs.} The LLM baseline in this thesis is deliberately restricted to structured text descriptions of each trial, to isolate text-based associative reasoning from perception (Section~\ref{sec:llm_baseline}). Gemini~2.5~Flash is natively multimodal, so re-running the same pre-registered rubric with the trial's rendered image or point-cloud visualisation supplied as an additional input is a low-cost extension (API calls against an already-built pipeline, not new engineering) that removes this handicap. If the SCM's advantage persists once the LLM can see what the SCM encodes structurally, the comparison in this thesis is strengthened; if the LLM improves substantially, that is itself an interesting and reportable finding about the marginal value of structural knowledge versus raw visual evidence, not a failure of the thesis's argument.

  \item \textbf{Physical constraints.} Extend the variable set to include physical constraints such as surface friction, object mass, and grasp force as a second causal pathway operating through contact mechanics rather than perception.

  \item \textbf{Non-linear SCM.} Investigate non-linear parameterisations of the structural equations, such as neural network models, which may better capture the non-linear relationships between noise level and grasp quality (e.g.\ the $\phi = 30°$ CGN bias, Section~\ref{sec:structural_equations}).

  \item \textbf{Empirical check of the NPSEM-ie assumption.} The mechanistic independence argument for $U_C, U_q, U_n, U_e$ given in Section~\ref{sec:counterfactual_diagnosis} could be tested directly by computing pairwise correlations of the fitted OLS/logistic residuals across the four structural equations. Strong residual correlation would indicate a shared unmodelled common cause and would weaken the validity of the abduction step.

  \item \textbf{Real robot validation.} Validate the framework on a physical Franka Panda with a real depth sensor, comparing the causal diagnoses against failures induced by controlled physical perturbations.

  \item \textbf{Closed-loop recovery.} Use the causal diagnosis to close the loop into a recovery policy: if the diagnosis attributes a failure to viewpoint, the system could autonomously reposition the camera; if it attributes the failure to noise, it could switch to a more robust sensor mode or apply stronger filtering.

  \item \textbf{Multiple objects.} Extend the experimental protocol to include objects of varying geometry, size, and material properties to test the generalisability of the causal model.

  \item \textbf{Causal discovery.} Apply causal discovery algorithms to the collected dataset to test whether the expert-specified DAG structure is supported by the data.
\end{itemize}

\chapter{Conclusion}
\label{ch:conclusion}

This thesis formulated robotic grasp failure diagnosis as a causal inference problem, and built the complete simulation-to-diagnosis pipeline needed to test that formulation: a Structural Causal Model linking four independently controllable perceptual variables to grasp outcome through measurable intermediates, implemented within a MuJoCo environment that reconstructs a Franka Panda arm from primitive shapes and integrates Contact-GraspNet for grasp synthesis, and exercised across 432 fully automated trials on a full factorial grid. The descriptive results reported in Chapter~\ref{ch:results} already support the central premise of the causal formulation: depth noise is not merely correlated with failure but behaves as its dominant driver, with success falling monotonically from 70.4\% under a noise-free sensor to 0.0\% under the most severe condition, while viewpoint and sparsity contribute smaller effects that interact with noise rather than acting independently. What remains is to close the loop that motivated the thesis in the first place---applying Pearl's three-step counterfactual procedure to attribute individual failures to their root cause, and testing whether this structured attribution outperforms a zero-shot vision-language model on accuracy, consistency, and explanation quality.

Engineering this pipeline surfaced problems that are easy to underestimate on paper: getting joint indices right in MuJoCo's flat state vectors, reconciling MuJoCo's and OpenCV's opposing camera conventions, and accepting that a primitive-shape gripper cannot reproduce the fine contact mechanics needed for reliable physical lifting. The last of these motivated the shift from a physical-lift criterion to the proximity-based criterion used throughout this report---a change made to preserve causal validity rather than to work around a difficulty, since the proximity criterion measures exactly the quantity the SCM is designed to explain.

The result is a reproducible experimental protocol and diagnosis pipeline that is not tied to Contact-GraspNet specifically: any grasp synthesis model and any simulation environment providing depth rendering and ground-truth object positions could be substituted without altering the underlying causal argument.

\chapter{IK Controller Implementation}
\label{app:ik_code}

The complete inverse kinematics controller implementation from \texttt{run\_experiments.py}:

\begin{lstlisting}[caption={Damped Least Squares IK controller.},label={lst:ik_full}]
def ik_move_to(model, data, target_pos,
               max_steps=2000, tol=0.010, lam=0.01):
    """
    Jacobian DLS IK for the 7 Panda arm joints.

    qpos layout (nq=16):
      [0:7]   freejoint of target_object
      [7:14]  arm joints 1-7
      [14:16] finger joints 1-2

    nv layout (nv=15):
      [0:6]   freejoint velocity DOFs
      [6:13]  arm joint velocities 1-7
      [13:15] finger joint velocities
    """
    site_id    = mujoco.mj_name2id(
        model, mujoco.mjtObj.mjOBJ_SITE, EE_SITE)
    jacp       = np.zeros((3, model.nv))
    ARM_QPOS   = slice(7, 14)
    ARM_VEL    = slice(6, 13)
    arm_ranges = model.jnt_range[1:8]

    for _ in range(max_steps):
        mujoco.mj_forward(model, data)
        err = target_pos - data.site_xpos[site_id]
        if np.linalg.norm(err) < tol:
            return True
        mujoco.mj_jacSite(model, data, jacp,
                          None, site_id)
        J  = jacp[:, ARM_VEL]   # (3, 7)
        dq = J.T @ np.linalg.solve(
            J @ J.T + lam * np.eye(3), err)
        sc = min(0.5,
                 0.1 / (np.linalg.norm(dq) + 1e-8))
        data.qpos[ARM_QPOS] += dq * sc
        np.clip(data.qpos[ARM_QPOS],
                arm_ranges[:, 0], arm_ranges[:, 1],
                out=data.qpos[ARM_QPOS])
        data.ctrl[:7] = data.qpos[ARM_QPOS]
        mujoco.mj_step(model, data)
    return False
\end{lstlisting}
